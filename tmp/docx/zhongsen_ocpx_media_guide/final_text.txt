1. 文档说明

本文面向接入中森跃动 OCPX 监测与转化回传能力的媒体、广告平台及第三方 DSP。媒体在发生
曝光或点击时调用中森跃动分配的监测地址；中森跃动完成数据接收、归因匹配与规则处理后，
将转化事件回传至媒体在点击请求中携带的回调地址。

 协议边界 本文件说明当前通用 GET 接入方式。专用签名、白名单、特殊事件映射或其他媒体方言，
 必须在联调时单独确认，不自动继承本文示例。


1.1 角色约定

 角色                 主要职责

 媒体 / DSP           触发曝光、点击监测请求，并提供可公网访问的转化回调地址。

 中森跃动               接收监测请求，完成事件事实、去重、归因与回传规则处理。

 广告主 / 上游 DSP       接收曝光或点击并识别后续转化，再回传转化事件。

1.3 快速接入步骤

  1. 获取监测地址：由中森跃动运营人员分别提供曝光监测地址和点击监测地址。
  2. 配置宏替换：按本文参数表替换媒体宏，重点确认 request_id 与 callback_url。
  3. 发送监测请求：曝光或点击发生时，以 HTTP GET 调用对应地址。
  4. 接收转化回调：媒体提供公网 HTTP/HTTPS callback_url，并接收 event_type 与可选
     currency_amount。
  5. 完成联调验收：核对宏值、URL 编码、HTTP 状态、去重行为和事件映射。

2. 监测地址获取与使用规则

媒体或第三方 DSP 完成接入信息确认后，由中森跃动运营人员按监测任务提供两条地址：

  • 曝光监测地址：固定携带 event=IMP。
  • 点击监测地址：固定携带 event=CLK。

 重要 地址中的 mId、tId、aId、lId 与 event 为中森跃动生成的固定路由参数。媒体只替换宏值，
 不得删除、重命名或改写这些参数。


2.1 地址模板

 GET https://{中森跃动分配域名}/ocpx/feedback?
   request_id=__REQUEST_ID__&callback_url=__CALLBACK_URL__&
   event=CLK&mId={固定值}&tId={固定值}&aId={固定值}&lId={固定值}

最终地址可能包含双方约定的更多设备或广告层级宏。以上域名与固定值仅用于展示结构，不是
可直接调用的生产地址。


2.2 通用请求要求

 项目                   要求

 传输协议                 HTTP / HTTPS；生产环境建议仅使用 HTTPS。

 请求方法                 GET

 字符编码                 UTF-8

 Content-Type         无请求体；参数位于 Query String。

 超时与重试                由媒体侧按双方联调策略配置；request_id 必须保持不变，以便幂等识别。

3.6 成功响应与状态码

 HTTP/1.1 200 OK
 {"ret":0,"code":200,"msg":"提交成功","data":{}}


 HTTP 状态码           含义

 200                当前事件事实事务提交成功；不代表上游广告主已完成接收。

 400                缺少固定路由参数，或请求包含已退役的旧路由参数。

 500                事件事实、计费或小时汇总事务失败；媒体可按约定策略重试。




4. 转化事件回传

广告主侧转化被中森跃动接收并完成归因、去重与规则处理后，中森跃动读取原点击请求中的 c
allback_url，并以 HTTP GET 向媒体回传转化事件。回调地址已有 Query 参数时使用 & 追加，
否则使用 ? 追加。


4.1 回调参数

 参数                 必填         类型             说明

 event_type         是          整数             中森跃动标准转化事件编号，取值见 4.3。

                                              支付类事件可携带金额。按合作方原始十进制金额透
 currency_amount    否          十进制数           传，不自动按“分”换算；币种与单位须在联调时固
                                              定。




4.2 回调示例

媒体在点击请求中提供的原始回调地址：
 https://media.example.invalid/ocpx/callback?click_id=abc123

中森跃动回传“激活”事件：
 GET https://media.example.invalid/ocpx/callback?click_id=abc123&event_type=1

中森跃动回传“付费”事件，并携带金额：
 GET https://media.example.invalid/ocpx/callback?
 click_id=abc123&event_type=5&currency_amount=123.45

4.4 媒体回调响应

媒体回调服务应返回 HTTP 2xx 表示成功接收。中森跃动通用回传不依赖响应 Body 的固定 JSON
结构；如需业务码校验、签名、重试或幂等确认，须作为专用协议另行约定。

5. 编码、安全与合规

  • callback_url、ua、caid_list 等可能包含保留字符的值必须整体 URL Encode，避免 &、
    =、? 被误解析为外层参数。
  • callback_url 仅允许公网 HTTP/HTTPS 地址，不得包含用户名密码、URL Fragment，不得
    指向 localhost、内网、链路本地或保留域名。
  • 设备标识仅在业务必要、合法且获得适当授权时传输；优先使用符合平台规则的标识或散列
    值，并遵循数据最小化原则。
  • 不得在文档、聊天记录或工单中明文传递生产密钥、签名材料、完整设备标识或真实用户数
    据。
  • 媒体侧应使用 request_id 实现幂等；同一事件重试不得生成新的 request_id。
  • 生产域名、IP 白名单、签名或专用适配器配置，以双方确认的联调记录为准。



6. 联调验收清单

 检查项                验收标准

 监测地址               已获得曝光与点击两条地址；固定路由参数未被修改。

 宏替换                宏均被真实值替换；未替换宏不会被当作真实设备标识。

 唯一请求               request_id 在同一事件重试时保持一致。

 URL 编码             callback_url、ua、caid_list 等已按 UTF-8 正确编码，且只编码一次。

 设备参数               至少提供双方约定的归因标识；采集合规与授权已确认。

 监测响应               成功请求收到 HTTP 200 与标准 JSON；失败场景能识别 400/500。

 回调可达               callback_url 为公网 HTTP/HTTPS 地址，中森跃动侧可访问。

 事件映射               仅使用已确认的 event_type；12–17 未确认前不启用。

 金额口径               支付金额的币种、单位与小数精度已书面确认。

 验收边界               合成联调、第三方 UAT 与生产验收的证据已分别记录。
