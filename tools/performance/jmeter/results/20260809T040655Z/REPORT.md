# SCX OCPX 本地 JMeter 压测报告

## 结论

- 本次严格通过的最高本地档位：300 QPS。
- 首个失败档位：600 QPS；失败档及其后的档位不计入通过结论。
- 20,000 QPS 60 秒本地突发：未达到或未执行。
- 口径仅适用于本地 Docker 4 CPU / 约 8 GB 隔离环境；不构成生产 20,000 QPS 验收。
- 不丢数结论只覆盖 HTTP 已明确受理的唯一事件，并要求 MySQL 事实 + 接入 DLQ 精确闭合且 Redis pending/lag 最终为 0。
- 未完成档位：1000 QPS（中止数据，不纳入统计）。

## 功能、故障与 Callback 对账

- 功能请求状态：200=1; 202=28; 409=1；覆盖 Android/iOS 字段矩阵、同 ID 200、载荷冲突 409、设备窗口并发竞争、窗口过期和无设备降级。
- 故障注入：副本不足=503，主 Redis 中断=CLIENT_ERROR，Pending 接管排空=30 秒，非法消息 DLQ=1。
- Callback：事实=611，扣量决策=611，下游任务=611，唯一幂等键=611，HTTP 尝试=1833，最终坏状态=0。
- 600 QPS 失败原因：202=180230; 503=2；明确 202=180230，但事实+DLQ=180232，存在 2 条未明确受理后仍落库的写入，且 failures=2。

原始证据见 `functional-results.json`、`functional-reconcile.txt`、`fault-results.txt`、`callback-qps100/callback-reconcile.txt`、各档 `summary.json`、`resources.tsv`、`reconcile.txt` 和 JTL。

## 正式容量验收边界

正式 20,000 QPS 仍需独立压测机、至少两台数据面实例、分布式 JMeter、持续 30 分钟、实例故障接管及真实第三方 UAT。
