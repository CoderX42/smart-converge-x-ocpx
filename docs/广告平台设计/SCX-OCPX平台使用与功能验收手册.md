# SCX OCPX 平台使用与功能验收手册（V70 前历史基线）

> 更新日期：2026-07-27
>
> 本文记录已退出当前 OCPX 构建的历史 OCPX 沙箱，不再作为当前接口或能力验收依据。V70 / Coco 首接请使用 [OCPX 双向转发引擎实现说明](OCPX双向转发引擎实现说明.md)、[通用渠道 OCPX 接入指南](通用渠道OCPX接入指南.md) 和 `contracts/`。本文所列 `/open-api/events/v1`、旧归因/RTA/RocketMQ 能力不能视为当前已交付。

> 当前结论：可用于内部沙箱研发和本地闭环验证；尚不能作为完整商业 OCPX 平台或生产媒体接入
> 平台验收。

## 1. 当前已实现的业务能力

| 功能域 | 当前可用能力 | 验收边界 |
|---|---|---|
| 账号与权限 | 登录、用户/角色/菜单/按钮权限、媒体对象范围 | 仍需目标环境多角色浏览器回归 |
| 主数据 | 媒体、合作方、客户、产品、渠道、渠道用户、接入文档 | 不是完整广告主/代理/广告账户/合同体系 |
| 追踪配置 | 短链、追踪链接、监测任务、事件映射、状态历史 | 不是 Campaign/AdGroup/Ad 投放模型 |
| 渠道接入 | 独立凭据、一次性密钥、轮换/吊销、端点权限、签名、nonce、限流 | 真实渠道 UAT 未签收 |
| 数据接入 | 点击、转化、回执、设备内部 HMAC、幂等、去重 | 生产容量未通过 |
| 归因 | Last Click 基础归因、原因码、人工复核、限量 | 尚无多触点或智能优化算法 |
| 回传与队列 | Callback、重试、死信、人工重放、Outbox、队列概览 | RocketMQ 全链路恢复仍需目标环境验证 |
| RTA | 端点配置、决策、日志、缓存和快速失败 | 不等于自有 RTB/DSP |
| 报表 | 日报、维度汇总、漏斗、事件明细、异步导出 | 无商业、账务、发票、结算报表 |
| 系统运维 | 审计日志、配置门禁、当前态 schema、显式前向 SQL 和 Runbook | 未完成生产发布演练 |

## 2. 当前不能满足的 OCPX 能力

当前系统不能完整满足以下能力：

- 广告主、代理商、子代理商、广告账户、合同、授信和商务政策。
- 虚拟账户、双分录账本、充值、调账、退款、冻结、结算和发票。
- Campaign、AdGroup、Ad、预算、排期、出价、素材组合和审核。
- 媒体库存、流量位、版位、设备/地域定向、频控和屏蔽策略。
- 真实媒体账户授权、对象同步、投放状态同步和成本回流。
- 以 CPA 50 CNY 为目标的自动调价、预算分配、探索/利用和模型实验。
- 商业/投放/归因/财务的全域对账以及生产级 SLA。

因此，对“是否满足附件中的完整 OCPX 功能体系”的回答是：**不能；当前是归因、回传、RTA
和运营报表基础较完整的研发沙箱，不是完整商业投放平台。**

## 3. R1-00 管理端验收

### 3.1 媒体对象范围

准备四类账号：管理员、已授权媒体的运营、已授权媒体的分析员、无媒体范围用户。

验收要求：

1. 管理员可读写所有媒体资源。
2. 运营只能读写授权媒体。
3. 分析员只能读取授权媒体，写操作失败。
4. 无范围用户不能读取或写入媒体资源。
5. 无权限与资源不存在返回一致结果，响应和日志不泄露对象存在性。

### 3.2 渠道客户端

在“投放配置 / 渠道客户端”选择媒体后：

1. 创建来源编码，至少选择 `CLICK`、`CONVERSION`、`RTA` 之一。
2. 一次性保存 `clientId`、`keyVersion` 和 secret；关闭弹窗后不得再次查看 secret。
3. 轮换密钥，确认新版本立即可用、旧版本在 24 小时重叠窗口后失效。
4. 当前版本不能直接吊销；旧版本吊销后立即拒绝。
5. 正确签名但调用未授权端点返回 `403`；未知机器端点也返回 `403`。
6. 不同媒体不能读取或操作彼此的渠道客户端。

### 3.3 事件与回执

按[通用渠道 OCPX 接入指南](通用渠道OCPX接入指南.md)签名请求：

1. 首次点击可靠受理；相同载荷重投幂等；相同 `eventId` 不同载荷冲突。
2. 转化必须携带业务事件键。
3. 回执只能由本渠道查询。
4. 点击回执不返回归因字段。
5. 转化处理后回执返回当前 `attributionStatus` 与 `reasonCode`。
6. 错误签名、过期时间、nonce 重放、端点越权分别产生稳定错误码。

## 4. 数据库验收

使用受控、可丢弃的 MySQL 8 环境。旧的一次性隔离验证脚本已在宝塔运维收口时移除；空库按当前态 schema 初始化，已有库只显式执行已批准的前向 SQL，再运行：

```bash
make db-verify
```

验收内容包括：

- 空库当前态 schema。
- 保留代表数据的前向升级。
- 前向 SQL 的重复执行策略和部分失败恢复。
- Git 提交、脚本名和 SHA-256 与发布清单一致。
- V43 审计字段、V44 端点权限、V45 数据库时钟修复、V46 菜单融合。
- Raw Event、Outbox、Callback 三类双 Worker `SKIP LOCKED` 竞争。

`init-database.sh` 只允许空库初始化；已有库升级必须由已授权人员显式执行发布清单中的前向 SQL。
不得修改已执行迁移、跳过 SHA-256 核对、使用数据库迁移账本或对业务库执行破坏性清理。

git diff --check

ESLint、Prettier、单元测试和生产构建；不得将基线噪声伪装成本次通过，也不得擅自扩大修改范围。
