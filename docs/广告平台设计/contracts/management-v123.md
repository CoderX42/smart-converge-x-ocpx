# 流程日志检索性能契约 V123

## 查询行为

- `GET /ocpx/flow-logs` 保留日期、流程、阶段、结果、事件 ID 与四实体筛选。
- 总数查询最多扫描 10,001 条匹配记录。匹配不超过 10,000 条时返回精确总数和
  `totalCapped=false`；超过时返回 `total=10000,totalCapped=true`。
- 前端在 `totalCapped=true` 时明确提示“仅支持查看前 10,000 条”，用户必须缩小日期范围或增加
  广告主、推广链接、媒体、监测任务、流程、阶段、结果或事件 ID 条件继续定位。
- 服务端拒绝偏移量超过 10,000 条的直接请求，避免绕过页面制造深分页扫描。

## 排序与索引

- 列表按 `event_time DESC,id DESC` 返回，与页面展示的“时间”字段一致。
- V123 为 `scx_ocpx_flow_log` 增加 `(event_time,id)` 索引，使默认首页从最新事件开始有序读取，
  不再按 `create_time` 对日期范围内的数百万行执行额外排序。

## 发布边界

V123 不修改或删除流程日志业务数据。目标表数据量较大，生产执行索引 DDL 前必须完成备份、
目标身份确认、SQL 与在线 DDL 能力审核并取得明确授权；源码和本地门禁通过不代表目标库迁移、
部署或线上性能验收完成。
