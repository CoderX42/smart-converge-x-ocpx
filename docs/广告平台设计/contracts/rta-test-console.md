# 监测任务 RTA 决策测试

2026-09-09。入口：监测任务列表 → RTA 列 → **RTA 测试**。这是独立的决策测试，原“测试链接”仍用于点击链路。

## 首版能力

支持现有 OPPO 媒体 → SCX 正式 OPPO RTA HTTP 接口 → 微风 WEIFENG_RTA 的单任务询量。自动显示监测任务、媒体、策略 ID、微风 aid/did、固定 Engine 请求地址；填写设备 OAID 或生成随机值后执行。随机 OAID 只能验证格式和链路，不保证上游允许。

返回同步允许/未获允许/异常、HTTP 状态、往返耗时、Redis 决策状态和原因码、SCX/供应商请求 ID、上游派发次数，并可跳转 RTA 流程日志。页面不会把 HTTP 200 或 Redis 的 ALLOW 单独冒充一次已成功返回的允许响应。

首版不自动发送点击或 Callback，不产生 SCX 点击/转化计费；会发送真实上游询量并计入既有 RTA 记录与统计。后台发起的测试不能证明 OPPO 公网来向、媒体签名配置或完整点击回传已验收。通用异步媒体、多策略批量、故障注入和压力测试仍使用现有自动化测试，不在此单任务入口伪造成功结果。

## 配置与权限

- 复用 `ocpx:monitor-task:test` 权限，并在服务层校验真实系统管理员。三项接口均禁止缓存；不新增权限、表或数据库迁移。
- Boot 使用 `scx.ocpx.admin.tracking.engine-base-url` 固定 Engine 地址，不接受浏览器传入的 URL、签名、媒体 ID 或策略 ID。正式地址须 HTTPS；HTTP 仅允许显式 localhost/loopback。
- 在 Boot 的 `app.rta-relay.credentials` 配置本次媒体凭据引用对应的密钥，值须与 Engine 的同名媒体密钥一致；至少32字符。密钥仅在服务端使用，不返回浏览器、不存测试结果或日志。该测试需要 Boot 持有媒体签名密钥，配置后需重新打包；如不希望向 Boot 配置该密钥，入口保留阻塞说明，不绕过签名。
- 媒体、上游接入、任务绑定及任务 RTA 均须启用，微风点击链接的 aid/did 须匹配。当前选择不支持的媒体/上游时显示明确阻塞原因。
- Nginx 若对 RTA 入口限制出口地址，必须允许 Boot 所在服务器的出口；本次不自动更改生产网关白名单。

## 执行与数据

管理端 `GET /boot/ocpx/monitor-tasks/{taskId}/rta-test` 读取配置及生成随机测试ID；`POST` 同路径接受 requestId/oaid 执行；`GET .../rta-test/{requestId}` 查询结果。

POST 重新校验真实任务路由，服务端按媒体配置生成 owner_id 和 MD5 签名，再发送至实际 `/ocpx/rta/oppo/{code}`。复用现有数据面校验、派发、Redis状态机、超时及日志，不增加放行捷径。

在发送前原子占用 Redis `scx:{rta-async}:admin-test:{requestId}`，保留任务/媒体/策略关联、设备单向指纹和安全结果24小时。相同测试ID不重复发送；更换设备须创建新测试。传输结果不明或发送进程中断时只能查询状态，不自动重发。不同任务不能读取同一测试结果。

仅存安全白名单结果，不保存 OAID 原文、完整上游body、签名或密钥。HTTP 无重定向，整体等待上限8秒，响应最多64KiB；超过限额按结果未知处理。RTA原有幂等与状态TTL保持不变。

页面自动查询最多15轮，可以手动刷新。失败后按钮不会自动重复提交。若请求在创建Redis记录前即被拒绝，查询可能显示不存在；修复配置后通过“新建测试”创建新ID。

本入口服务于手工联调，不替代 RTA 优化方案中的并发竞态、双实例恢复、完整账务闭环及容量验收。未自动执行任何真实合作方请求。
