# 上游 Callback 转化记录契约 V118

## 目标与事实口径

- 管理端新增“上游转化记录”页面，对应只读接口 `GET /ocpx/callback-records`。
- 唯一数据源是 `scx_ocpx_event_fact` 中 `flow_type='CALLBACK'` 的事实，不从流程日志、
  Redis 或小时汇总反推明细。
- 唯一事实按广告主、监测任务、`request_id` 和事件代码幂等；合作方对同一转化的重试
  不产生第二条转化记录。重试次数、请求结果和响应预览继续到流程日志查看。

## 查询与返回

- 默认查询最近 7 个自然日，最大跨度 366 天；支持广告主、推广链接、媒体、监测任务、
  事件、是否目标转化、扣量判定和精确 `requestId` 筛选，分页最大 100 条。
- 每条记录返回四个业务主体及名称、事件、上游接收时间、目标转化标记、广告主计费结果、
  消费金额、订单金额、扣量判定、实际放行率快照和判定时间。
- `PENDING` 表示 SCX 尚未完成扣量判定；`DEDUCTED` 表示 SCX 已拦截；`PASSED` 表示
  SCX 已提交下游投递，不表示媒体已经签收或完成业务入库。
- V113 前没有持久化扣量判定的历史 Callback 显示为“历史无判定数据”，不得伪装成 `PENDING`，
  也不得按当前扣量比例反推。
- `REJECTED_INSUFFICIENT_BALANCE` 只表示本次转化计费因余额不足被拒绝，转化事实仍然保留，
  并继续执行既有媒体扣量流程。

## 权限与安全

- 页面和接口使用 `ocpx:callback-record:view`。`ROLE_ADMIN` 默认拥有；共享
  `ROLE_ADVERTISER` 默认拥有并仍可由管理员配置。
- 服务端必须通过 `AdvertiserScope` 强制广告主数据范围，不能依赖前端隐藏筛选项。
- 列表不返回设备标识、Callback URL、签名、凭据或原始请求参数。需要诊断请求时，页面仅跳转到
  现有流程日志；其详情继续受更高权限和 `no-store` 约束。

V118 只增加只读接口、页面菜单和权限，不修改既有 Callback 接收、计费、扣量、投递、去重或
事实表结构。目标库迁移、应用重新打包、部署、重启及真实合作方 UAT 仍需独立证据。
