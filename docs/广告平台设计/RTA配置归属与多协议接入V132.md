# RTA 配置归属与多协议接入 V132

日期：2026-09-08。状态：源码、模拟闭环和隔离环境验证完成；未部署生产、未调用微风真实接口。决策依据见 [ADR-017](adr/ADR-017-RTA多协议与配置归属.md) 与 [RFC](RFC-RTA多上游协议扩展方案.md)。本文更新 V131 的后台入口与上游协议边界，媒体认证、异步通知、日志及统计契约继续沿用。

## 后台入口

- 广告主管理 → 某广告主的“RTA 配置”：维护多份上游接入；列表显示已启用数和总数。
- 媒体管理 → 某媒体的“RTA 配置”：维护该现有媒体唯一的 RTA 配置，通知地址和凭据引用属于媒体。
- 监测任务 → 某任务的“RTA 配置”：选择该任务广告主的上游接入。媒体和广告主从任务读取，不能在绑定里改变。
- RTA 管理：仅保留请求记录、流程日志、统计报表。请求详情可打开关联日志。

配置抽屉锁定所属对象，并通过地址查询参数支持刷新直达。三类配置的旧独立页面已经移除。数据接口保留原权限码，权限项归到所属管理页面；普通角色授权不自动扩大。角色需要所属主页面的查看权限，以及对应 RTA 查看/编辑权限；只有编辑权限不会自动获得其他对象的数据范围。

## 微风配置步骤

1. 在现有广告主管理中选择微风对应的广告主。广告主的非 RTA 上游协议按既有点击业务配置为 `WEIFENG`，它与本次单独选择的 RTA 协议各自负责对应业务。
2. 进入该广告主“RTA 配置”，新建接入，协议选择“微风 RTA”。地址固定为 `https://rta.adapi.cn/rtaCommon/sendRta`；分别填写 `aid=5103`、`did=zsyd`。不需要把查询参数重复拼进地址，也不填写通用 HMAC 凭据或决策回调地址。等待时限默认 5000 毫秒，放行有效期默认 300 秒。
3. 新建配置默认停用，确认后显式启用。一份微风接入对应一个 aid/did 组合；同一广告主的其他计划新增另一份接入。保存后协议不可修改，更换协议应新建接入并修改任务绑定。
4. 在实际下游媒体的“RTA 配置”中填写 HTTPS 决策通知地址、服务端媒体凭据引用并启用。这里选择的是现有媒体，不新建另一套渠道。微风的 did 是合作方标识，不是 SCX 的 mediaId。
5. 检查监测任务使用的推广链接：微风点击地址必须具有与该接入一致的字面量 aid/did。打开任务“RTA 配置”，选择刚创建的接入并启用绑定。微风无需填写上游产品 ID/任务 ID；后端会校验任务广告主、媒体状态及计划匹配。
6. 媒体按 [异步契约](contracts/rta-async.md) 签名请求 `POST /ocpx/rta/requests`。微风接入每次只能提交一个 SCX taskId，`context.os` 为 ios/android，设备提供有效的设备标识。媒体凭据解析出的 mediaId 必须与该任务一致。
7. 媒体收到 202 受理信息后等待 SCX 的独立 HTTP 通知。Engine 在后台请求微风，解析其同步 `{id, code}` 响应：id 必须匹配，code 为 0 放行唯一候选任务，非 0 拒绝。异常响应进入 ERROR，超时进入 TIMEOUT。202 本身不允许投放。
8. 媒体收到 ALLOW 后，在有效期内按原 Feedback 契约提交事件，使用独立 `rtaRequestId` 关联 SCX relayRequestId；事件自己的 requestId 不变。SCX 校验媒体、命中任务、有效期和绑定版本，并把已校验的供应商 RTA ID 写入微风点击的 requestId，支持 `__RID__` 宏。

微风文档没有完整曝光外发地址，本版完成本地曝光门禁和点击关联；真实曝光发送需取得正式地址和契约后补齐。设备原值与 MD5 字段存在文档歧义，当前优先发送明确的 MD5 字段，已有 MD5 不重复哈希，CAID 新旧字段独立映射。正式接入仍需合作方确认设备字段及点击关联效果。

## 服务端准备

Boot 与 Engine 都使用 `app.rta-relay.allowed-hosts` 校验出站目标，需要按部署环境允许 `rta.adapi.cn` 和媒体通知域名；通用异步接入还需允许其上游域名。使用精确域名、HTTPS、公网解析校验，不允许任意跳转。微风仅由适配器生成 aid/did 两个参数。

媒体凭据、通用异步上游凭据及 Redis 短存报文加密配置继续由服务端解析；密钥不下发浏览器。配置依照项目规则直写各自 profile 配置文件，重新打包并重启后生效。本次没有填写生产密钥或改动线上配置。

新协议需要在 Core 注册协议定义并在 Engine 实现 `RtaUpstreamAdapter`，新增配置/请求/响应/回调测试，随 Boot 与 Engine 同版本发布。协议定义包括模式、候选上限、配置字段、绑定字段及重试能力；新增同一协议的接入可直接在后台配置。后台不支持在线脚本或任意协议执行。

通用异步继续采用 HMAC、最多 100 个候选、上游 202 受理及独立回调。微风文档没有承诺幂等重试，派发前原子标记 SENT，已派发的未知结果在重启后不会重发，最终按截止时间超时；共享通知重试和终态规则不变。

## SQL、切换与回退

已有 V131 环境仅使用新增的 [V132 前向 SQL](../../scx-backend/scx-boot/src/main/resources/db/migration/V132__extend_rta_protocols_and_embed_configuration.sql)，不重放 V131，不执行空库初始化。V132 扩展协议配置和结构版本，放宽协议相关绑定字段，将原配置菜单转为对应管理页面的权限项，保留 ID 和既有授权。既有通用异步接入的参数和启用状态不变，不生成微风接入。

V132 文件 SHA-256：`0fd2be3bf52f234f8aef9ee0cd2411359f097f92e6c4daf15fa0ca363ddc1547`。

空库使用已同步的当前态 schema。没有新增表，无需变更必需表清单；校验脚本已更新列、菜单和权限归属检查。

发布顺序：备份并确认目标环境、预览 SQL 及影响权限 → 暂停新 RTA 受理并核对待决策/通知队列 → 人工授权执行 V132 → 核对结构和数据、运行 verify-database → 同版本发布 Boot、Engine、前端 → 更新角色所需主页面权限并刷新菜单缓存/登录状态 → 配置联调成功后显式启用接入、恢复受理。源码交付不自动执行以上生产步骤。

旧 Redis 快照缺少协议字段时仅按既有 GENERIC_ASYNC 解析，不能当作微风结果。回退前停止新协议受理并处置在途请求、通知及仍有效的放行状态，避免旧 Engine 读取新协议状态。数据库扩展优先保留；恢复旧菜单和应用版本需要单独审阅发布包，不自动删表或撤销数据。Redis 丢失仍不承诺恢复全部已受理请求和未落库数据。

XXL-JOB 继续注册 `ocpxRtaLogFlushJob`（5 秒）、`ocpxRtaMetricFlushJob`（5 秒）、`ocpxRtaLogCleanupJob`（10 分钟），使用既有 Boot 执行器，单机串行落库。适配器不写 SQL、不新增应用内落库定时器。暂停这些任务仅延迟日志/报表；恢复后消费 Pending 并按幂等规则落库。继续监测积压、死信、任务失败、决策超时和统计延迟。
