# 基础平台、工程模块与运行边界

> 本文说明当前主源码实际存在的能力；与默认菜单可达性分开记录。全部 HTTP 方法的参数、返回类型和精确位置见 [源码接口索引](05-源码接口索引.md)。普通增删改查统一采用：查询参数或 JSON 实体 → 登录拦截及按接口注解执行动作权限校验（部分入口仅登录） → Controller → Service / MyBatis-Plus → MySQL → `Result{code,msg,data}`；实体字段见 [数据库字段索引](06-数据库字段索引.md)。不将这一通用路径等同于每个入口都有完整的对象级授权。

## 1. 身份认证与授权

| 功能 | 输入 → 输出 | 实际处理与存储 | 边界 |
|---|---|---|---|
| 账号登录 | username、AES 密文 password、滑块校验 code → SaTokenInfo | 前端可执行滑块；ValidateCodeFilter 的常量 `/token/login` 与当前 `/auth/token/login` 不匹配，不能认定服务端该过滤器覆盖当前登录入口；TobTokenController 解密密码；LoginService 读 SysUser / 角色菜单权限、BCrypt 比对、状态校验；SecurityUtils 建立 Sa-Token 会话 | AES 兼容编码不能替代 HTTPS；数据库存 BCrypt；不在报告中复制任何编码密钥 |
| 滑块验证码 | 类型/点位/临时 token → 图片及校验结果 | `/auth/code/get`、`/auth/code/check` 调用 CaptchaService，缓存由 CaptchaCacheRedisService 接入 Redis | vendored `/captcha/*` Controller 也有源码，是否被 captcha 自动配置注册需运行时路由确认，不按普通 Boot 包扫描直接断言 |
| 短信登录 | phone、code → SaTokenInfo | SmsValidateCodeFilter 从 `SMS_CODE_KEY + phone` 取码，匹配后删除；LoginService 复用账号状态和会话流程 | 当前源码未找到独立的公开发送验证码 HTTP 入口；配置/记录 CRUD 不等于已实现发短信闭环 |
| 社交登录 | 临时 code、平台 type → SaTokenInfo | RemoteSysUserService → SocialLoginFactory → WechatMiniLoginStrategy / WechatWebLoginStrategy，凭服务端配置获取 openId 并匹配绑定用户 | 依赖真实第三方配置；未实测第三方授权 |
| 登录状态/退出 | 当前 token → boolean / 空成功结果 | `/validate-token` 调用 isLogin；退出调用 StpUtil.logout | validate-token 在默认非匿名范围内，不能假设未登录时一定返回 false |

| 用户信息/动态菜单 | token → 用户资料、角色码、权限码、菜单树 | SysUserServiceImpl.findUserInfo 聚合角色菜单；SysMenuServiceImpl 构造登录用户菜单树 | 前端仍执行 `_core/ocpx/system` 组件白名单，数据库有菜单不保证页面可加载 |
| 广告主开户/注销 | advertiserId/name、username/rawPassword → userId/username | AdvertiserAccountProvisionerImpl 事务内校验含已删除用户名、固定 ROLE_ADVERTISER，BCrypt 后写 sys_user(type=2, shop_id=advertiserId) 与 sys_user_role；注销删关系、逻辑删用户并登出 | Admin 与此服务共用数据库事务；账号映射中 shop_id 复用为广告主 ID，不意味着多租户商城仍存在 |
| 广告主共享角色授权 | menuIds、allDataScope → 当前共享配置与受影响账号数 | 固定角色行锁；只允许可授权 OCPX 权限、补齐父级闭包、校验全量范围依赖；替换 role_menu；清缓存并注销全部广告主会话 | 充值/人工扣减/任务计费/测试/联调等关键权限不能通过该配置下放；实际服务层再次校验 |

## 4. Maven 依赖不能直接当作业务调用

- 当前聚合包含 auth、system、ocpx-core/admin/engine、common、visual、boot。Boot 显式依赖 auth、system-biz、ocpx-admin、generator、security/swagger/websocket/job；**不依赖 Engine**。
- Core 为共享实体和契约；Admin 与 Engine 分别依赖 Core。Engine 独立 Spring Boot 应用，不经过管理端 Sa-Token 会话实现媒体回传。
- common 共 18 个子模块：core、storage、mybatis、log-buffer、log、security、job、logistics、sms、swagger、redis、idempotent、dubbo、sentinel、seata、websocket、datasource、excel。它们是通用技术能力，不自动等于 18 个产品功能。
- 当前主源码扫描未发现 RocketMQ producer/listener 调用；存在依赖及配置不足以证明广告链路正在使用 RocketMQ。OCPX 实际通过同步 MySQL、Redis、HTTP 和本机线程池流转。
- Dubbo 注解和 cloud profile 仍留在通用模块；当前标准交付是 Boot 管理端与 Engine 两个业务进程，不能据此把系统画成已落地微服务集群。
- `scx_schema_migration` 已退役，不用于运行状态或结构版本判定。旧 migration、退役 SQL、旧领域文档不是当前 schema，也不代表相应业务仍被装配。
