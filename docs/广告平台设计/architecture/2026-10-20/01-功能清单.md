# 功能清单：按业务域归类

> “实现”指当前源码。每个 HTTP 方法的精确路径、输入签名、返回类型与权限注解在 [接口索引](05-源码接口索引.md)，表字段在 [数据库索引](06-数据库字段索引.md)。本页列业务语义；详解补充全部边界条件。

## 1. 广告业务管理

| 业务域 / 功能 | 输入 | 核心处理 | 输出 / 最终消费 | 当前边界 |
|---|---|---|---|---|
| 广告主列表/选项/详情 | 分页、关键词、advertiserId | 服务端业务范围过滤、统计链接/任务、按账户权限回填余额 | 广告主 DTO / 下拉选项 | 全量业务权限不等于可读他人资金 |
| 广告主开户 | 名称、用户名、原始密码、协议、凭据引用、模板等 | 事务创建 advertiser、零余额 CNY 账户、BCrypt 系统账号、共享角色关联 | 广告主详情、托管用户名 | 原始密码不进入广告业务表和响应 |
| 编辑/删除广告主 | advertiserId、修改字段 | 编辑后刷新标记；删除前锁广告主，存在余额/事实/账务/计费配置审计即拒绝；无历史时清所属依赖并注销账号 | 成功/明确拒绝 | 不能再写成“可任意级联删除全部经营历史” |
| 共享广告主权限 | menuIds、allDataScope | 固定角色行锁、权限白名单及父级闭包、替换菜单、清缓存、注销受影响会话 | 共享权限树及账号数 | 全体广告主共享；共享角色维护、充值、人工扣减、任务计费配置、测试及联调动作不可下放 |
| 推广链接 CRUD/下拉 | advertiserId、平台、链接名/URL、deeplink、扩展 | 主体关系验证、按协议模板校验、引用保护、逻辑删除 | 链接及归属 DTO | PHOENIX/人人视频/引力校验各不同；保存通过不等于 Engine 可投递 |
| 媒体 CRUD/宏目录 | 名称、uri、macroParams、凭据引用 | 名称唯一、宏目录/保留键/重复检查、历史引用保护 | 媒体配置、可插入宏清单 | 凭据引用与真实密钥分离；默认媒体页已有布局修改被保留 |
| 监测任务 CRUD/计费配置 | 广告主+链接+媒体、名称、价格、计费模式、目标事件 | 四维归属验证、新增或变更计费字段时校验内部计费权限、生成 IMP/CLK URL、计费前后 JSON 审计、逻辑删除 | 任务 DTO、showUrl/clkUrl | CRUD只生成URL；测试/联调另有出站入口 |
| 创意素材上传/复用 | advertiserId、图片 File | 自有主体校验、真实格式、扩展名与尺寸检查、尺寸/大小校验、SHA256、对象存储+sys_material | 图片 URL、materialId、尺寸、hash、重复提示 | 上传/创意保存两步；素材可以暂未绑定 |
| 图片创意 CRUD/多链接绑定 | 自有 materialId、名称、状态、同广告主 promotionLinkIds | 服务端重读图片、名称去重、创意行锁、事务替换多对多关联 | 创意与绑定链接 | 管理域功能；不引入 Engine cId 或创意计费/报表维度 |
| 媒体扣量规则 CRUD | linkId、mediaId、ratio 0..1 | 活跃路由唯一、MySQL规则、Redis Lua重置对应比例与计数 | 规则和比例 | 前端百分比÷100；仅决定 Callback 数量放行，不改变广告主费用 |
| 上游协议域名维护 | 协议、精确 host[] | 标准化/去重，事务替换允许域，标记刷新 | 允许域名集合 | 五种专用协议；TEMPLATE_GET 无相同策略链 |

详细逻辑、源码及权限三层区别见 [广告管理详解 §2](08-广告管理领域详解.md)。

## 2. 资金与经营分析

| 功能 | 输入 | 核心逻辑 | 输出 / 消费 |
|---|---|---|---|
| 充值 | advertiserId、requestId、amount、remark | 真实管理员；账户 FOR UPDATE；业务幂等键 RECHARGE；更新余额与不可变流水同事务 | entryId、金额、账后余额、时间 |
| 人工余额扣减 | 同上、必填原因 | 禁止透支；MANUAL_DEBIT 独立幂等；重放校验金额和原因 | 流水与余额；不计广告消费 |
| 广告点击/目标转化扣费 | Engine事实及当前任务配置 | 唯一事件去重；按模式/目标触发、资金行锁；不足写 REJECTED | 事实计费状态、POSTED/REJECTED流水、小时消费 |
| 账务流水查询 | 主体、任务、类型、状态、业务键、时间、分页 | 账户专有范围过滤；事实/任务关联查询 | 精确六位金额及余额前后值 |
| Dashboard | 可选四维、日期 | 小时指标聚合，Asia/Shanghai；零分母返回空；广告主仅读自有资金；内部用户可读筛选账户；账户消费固定今天 | 九项指标、account、businessDate、asOf |
| 时段报表 | YYYYMMDD日期、小时/日/月/年、四维、排序、分页 | SQL时段+四维聚合与分页；真实 Callback/放行/拦截/待判定口径 | records、分页；前端合计只汇总当前页 |
| hourly 分组 API | TIME/ADVERTISER/PROMOTION_LINK/MEDIA/MONITOR_TASK 等分组 | 先查全部聚合组，Java 分页及汇总 | 分组数据与 summary；当前页面主要用summary接口 |
| CSV导出 | 与时段报表一致的过滤 | 同范围查询全部结果，内存生成 UTF-8+BOM | 浏览器 Blob 下载；没有异步导出任务/对象存储产物闭环 |
| 上游 Callback 记录 | 日期、四维、requestId、事件、目标/扣量筛选 | 查询 `event_fact.flow_type=CALLBACK`，索引分页并精确count | 唯一转化事实、计费/扣量快照；不代表媒体签收 |
| 流程日志/详情 | 日期、四维、eventId、阶段/结果；详情ID | limit+1无精确count、最多前10000条；管理员详情关联trace/受限参数快照 | 阶段、HTTP、耗时、脱敏预览、hasNext、total（总数下界） |

来源：[管理详解](08-广告管理领域详解.md)、[引擎详解 §3.1/3.3](09-投递引擎领域详解.md)。余额、事实与流水以 MySQL 为准；旧 Redis 余额和兼容报表不是现行真相。

## 3. 实时投递、回传与决策

| 功能 | 输入 | 核心处理 | 输出 / 触发条件 |
|---|---|---|---|
| 通用曝光/点击接入 | GET Query，mId/tId/aId/lId、IMP/CLK、request_id、设备、callback_url | 标准化 → 可选RTA准入 → MySQL唯一事实/计费/指标 → 首次允许才投递 | 入口受理响应；仅 PHOENIX 支持上游曝光投递，其他协议主要CLICK |
| 六种上游事件适配 | 规范 Feedback + advertiser/link 配置 | TEMPLATE_GET、AERIM、WEIFENG、GRAVITY、RENREN_VIDEO、PHOENIX 各自宏、身份、时间、URL、安全校验、Callback上下文 | GET合作方URL；成功判定按各协议，详解有完整映射 |
| 七个Callback/测试入口 | 通用、五种专用回调和test-callback | 解密上下文/映射动作金额；正式路径写唯一事实/计费；测试收集器仅记录受控最后一跳 | 各协议空响应/JSON及状态码，不统一用管理 Result |
| 媒体扣量判定 | factId、路由、标准动作、配置比例 | Redis Lua累计比例判定，decision key支持待定恢复；MySQL PENDING条件更新最终决策 | PASSED或DEDUCTED，只有获胜PASSED提交媒体出站 |
| 普通媒体回传 | 原callback_url、标准event_type、可选金额 | URL解码一次、公网策略、追加字段、内存线程池GET | HTTP结果日志；200/204成功，无持久化补投 |
| 通用异步RTA | JSON requestId/taskIds/device/context + HMAC头 | 请求幂等、签名防重放、配置快照、Redis Lua INIT；worker发GENERIC_ASYNC或WEIFENG_RTA | 202受理；最终决策通过独立通知POST发送媒体 |
| RTA广告主异步决策 | relayRequestId/status/matched + HMAC | 校验原候选、过期及冲突；Lua终态一次性转移 | ALLOW/DENY/ERROR/TIMEOUT；ALLOW生成准入有效期 |
| RTA媒体通知/准入 | 最终决策、签名通知、独立rtaRequestId | 有限通知重试；Feedback核对媒体/任务/版本/期限 | 允许或拒绝曝光点击；普通RTA与普通Feedback验签边界不同 |
| OPPO同步RTA | OPPO JSON签名、整数strategy列表、OAID等 | 拆每策略内部微风RTA；受限线程等待Redis决策；SYNC_RETURNED | 同一次HTTP返回允许策略列表，默认relay关闭时不应称已启用 |
| OPPO受保护点击 | code/strategy、request_id/rta_request_id、OAID等 | 必须有已同步返回ALLOW且设备/配置匹配；转换Feedback后进入正式链 | 点击事实、可计费、上游转发 |
| OPPO激活/注册/付费回传 | Callback标准动作+受控设备hash/pkg/adId | 映射1/2/7、设备AES、body/header签名，POST固定uploadActiveData | HTTP2xx且ret=0判成功；当前没有持久化自动重试 |

完整入口、事件映射、状态码与顺序在 [引擎详解](09-投递引擎领域详解.md)，不是从历史协议文档直接抄录。

## 4. RTA管理与诊断

| 功能 | 输入 → 输出 | 实际规则与边界 |
|---|---|---|
| 广告主RTA接入 | 协议/endpoint/credentialRef/protocolConfig/超时/TTL/version → 接入配置 | 广告主抽屉维护一对多上游；真实管理员；version乐观锁；GENERIC_ASYNC与WEIFENG_RTA目录驱动 |
| 媒体RTA接入 | protocol/notifyUrl/credentialRef/config/version → 接入URL | 通用通知与OPPO分别校验；凭据只传引用；媒体抽屉承载 |
| 任务RTA绑定 | task/upstream/product/externalTask/oppoPkg/version → strategyId/配置 | 同广告主、启用关系、歧义校验；独立整数strategy，不等于任务ID |
| RTA实时记录 | 状态/媒体/任务/广告主/请求等 → Redis安全摘要 | 24小时索引扫描、读state后过滤与分页；不是MySQL历史事实列表 |
| RTA历史日志/统计 | 毫秒时间窗、维度 → 日志/请求数/决策/通知指标 | MySQL由XXL-JOB延迟刷入；返回dataAsOf，需区分实时状态 |
| 完整CLK测试 | task、平台、参数、REAL/SIMULATED → 预览/结果时间线 | 服务端固定Engine URL；可产生真实上游和计费；模拟仅最后媒体一跳。REAL依赖旧快照，当前存在数据来源缺口 |
| 下游媒体联调 | 已存feedbackLogId、动作、金额 → HTTP结果 | 直接发真实媒体；不生成正式转化、不扣费、不正式扣量；同样依赖旧快照 |
| RTA询量测试 | task、requestId、OAID → 预检/决策/日志定位 | 当前仅OPPO→微风；幂等ID不可随意重发；不自动点击/转化，计入RTA统计 |

## 5. 基础系统与运维覆盖

认证、用户/角色/菜单/部门、字典、全局配置、系统/登录日志、在线用户、服务器信息、存储、素材与分组、区划、短信配置/记录、三方账号、文章/分类、协议、启动广告、个人信息/密码、代码生成、WebSocket、独立监控、XXL-JOB中心及样例的输入输出与规则全部在 [基础平台详解](07-基础平台与运行边界.md)。其中：

- 默认系统导航仅8页；更多system组件/API是已存在但没有默认菜单的能力。
- 启动广告后端实现存在，前端页面仍为空状态；忘记密码/二维码不是已闭合功能。
- 短信登录有页面、验证码校验和登录入口，但发送wrapper没有当前匹配后端；图形验证码服务端Filter路径也有静态不一致。
- `gen`后端在Boot内，但现行前端白名单不加载生成器；其他订单/退款/商城/会员/微信平台源码残留不计当前广告业务。
- RocketMQ、Seata等库或配置存在，不证明广告主链正在使用消息队列或分布式事务。
