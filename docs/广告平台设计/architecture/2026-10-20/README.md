## 最需要先读的结论

1. **账务先于投递**：Feedback 和 Callback 的事实/计费先提交；普通上游与媒体（含 OPPO）出站使用本机线程池，当前没有持久化投递任务和自动补投闭环。已扣费、PASSED、HTTP 受理与对方业务签收是不同节点。
2. **媒体联调依赖断层**：REAL_MEDIA 点击测试及媒体联调读取旧 Feedback 快照；该路径默认关闭写入，即使开启兼容写入也清空 callbackUrl。接口存在不代表新流量可以直接提供可用联调样本。
3. **RTA 有实现但默认关闭**：通用异步和 OPPO 同步外观均已编码，依赖 Redis、有效协议配置、凭据及 XXL-JOB 落库；仓库公共/dev/prod 配置的 relay 开关为 false。
4. **跨存储一致性有限**：规则 MySQL 写入与 Redis 重置不同事务；配置刷新使用单个可删除标记；多 Engine 实例刷新和处理中配置快照需要特别关注。
5. **报表与日志必须按口径消费**：经营报表来自小时事实汇总；流程成功日志默认 10% 采样、同步写入；前端时段报表合计仅当前页；财务核对应读账务与事实。
