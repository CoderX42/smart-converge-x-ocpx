# 09 指标口径与报表字典

## 1. 统一口径原则

- 报表默认使用账户业务时区，存储统一 UTC；跨日事件按 `occurred_at` 归属，接收延迟单独记录。
- 实时报表是预估值，日结完成后为已确认值；页面必须显示状态和最后更新时间。
- 指标公式、有效性规则和计费口径都有版本；历史报表使用当时版本，不随新规则静默重算。
- 金额以整数最小货币单位计算，展示时按币种精度转换；聚合中禁止浮点累计。
- 同一报表请求必须返回 `timezone`、`currency`、`data_status`、`metric_version`。

## 2. 基础事实指标

| 指标代码 | 中文名 | 定义 |
| --- | --- | --- |
| requests | 广告请求 | 通过基本格式校验的广告请求；一期无 RTB 时可为空。 |
| responses | 广告响应 | 返回至少一个广告候选的响应；一期无 RTB 时可为空。 |
| impressions_raw | 原始展示 | 接收到的展示事件，包括重复和无效。 |
| impressions | 有效展示 | 验签、格式、幂等和基础风控通过的唯一展示。 |
| clicks_raw | 原始点击 | 接收到的点击事件，包括重复和无效。 |
| clicks | 有效点击 | 验签、格式、幂等和基础风控通过的唯一点击。 |
| conversions_raw | 原始转化 | 接收到的所有转化请求。 |
| conversions | 有效归因转化 | 通过校验且成功归因的唯一转化。 |
| billable_events | 可计费事件 | 满足对应计费规则、账期和质量确认条件的事件。 |
| spend | 广告主消耗 | 广告主侧已确认扣费之和。 |
| media_cost | 媒体成本 | 媒体侧已确认结算成本之和。 |
| revenue | 平台收入 | 若平台以广告主消耗作为收入，则等于广告主已确认消耗；必须由财务 ADR 固化。 |
| invalid_events | 无效事件 | 被重复、格式、签名、超窗或风控规则拒绝的事件。 |

## 3. 派生指标

| 指标 | 公式 | 除数为 0 |
| --- | --- | --- |
| Fill Rate | `responses / requests` | 返回 null，不返回 0% |
| CTR | `clicks / impressions` | null |
| CVR（点击） | `conversions / clicks` | null |
| CPM | `spend × 1000 / impressions` | null |
| CPC | `spend / clicks` | null |
| CPA | `spend / conversions` | null |
| eCPM | `spend × 1000 / impressions` | null |
| ROI | `conversion_value / spend` | null |
| 毛利 | `revenue - media_cost - adjustments` | 保留金额 |
| 毛利率 | `gross_profit / revenue` | null |
| 无效率 | `invalid_events / raw_events` | null |
| 回传成功率 | `callback_success / callback_due` | null |
| 归因成功率 | `attributed_conversions / valid_conversion_requests` | null |

`conversion_value` 只统计广告主明确上报且通过校验的价值；它不是平台收入。

## 4. 维度字典

| 维度 | 粒度/说明 | 基数风险 |
| --- | --- | --- |
| date/hour | 账户时区日期或小时 | 低 |
| advertiser | 广告主 | 低 |
| campaign/ad_group/ad/creative | 投放层级 | 中/高 |
| publisher/app/placement | 媒体库存层级 | 中 |
| event_type | IMPRESSION、CLICK、REGISTER、PAYMENT 等 | 低 |
| billing_type | CPM、CPC、CPA | 低 |
| country/province/city | 归一化地域代码 | 中 |
| os/device_type/network | 设备和网络分类 | 低 |
| risk_result | 放行、无效、延迟确认、拦截 | 低 |
| attribution_model/version | 归因模型和规则版本 | 中 |

默认报表禁止任意高基数 metadata 分组，防止分析库和导出失控。新增维度必须评估基数、脱敏和存储成本。

## 5. 数据状态

| 状态 | 含义 |
| --- | --- |
| REALTIME_ESTIMATED | 流式聚合结果，可能受迟到事件和风控复核影响。 |
| DAILY_PROVISIONAL | 日切后初步结果，对账未关闭。 |
| DAILY_CONFIRMED | 数据质量检查通过且日账确认。 |
| RESTATED | 因审批后的补数/冲正产生重述，保留原版本。 |

## 6. 迟到、重算和导出

- 迟到事件水位线默认 24 小时；超出后进入迟到队列，不直接覆盖已确认报表。
- 报表重算必须生成 `restate_batch_id`、原因、前后差异和审批记录。
- 导出记录查询条件、口径版本、操作者、文件哈希和过期时间。
- 报表 API 返回的总计必须在相同过滤范围内由服务端计算，不能简单累加当前分页。

## 7. 验收示例

给定 100 次展示上报，其中 5 次重复、3 次签名失败；有效展示为 92。给定 10 次有效点击和 2 次成功归因转化，CTR 为 `10/92`，点击 CVR 为 `2/10`。若消耗 20.00 元，CPA 为 10.00 元。所有金额在存储和计算中使用 2000 分，而非 20.00 浮点数。
