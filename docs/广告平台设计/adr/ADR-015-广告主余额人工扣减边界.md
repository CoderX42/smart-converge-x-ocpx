# ADR-015：广告主余额人工扣减边界

- 状态：Accepted
- 日期：2026-08-17
- 决策人：项目负责人

## 背景

V108 已以 MySQL 广告主账户、账户行锁和不可变账务流水作为余额真相，但管理端只有充值入口。运营需要在退款、线下调账等场景扣减广告主可用余额。直接修改余额、传负数充值或复用点击扣费都会破坏权限语义、幂等边界和账务可追溯性。

## 决策

1. 新增独立的 `POST /ocpx/advertisers/{id}/deduct`，不允许以负数调用充值接口。
2. 请求使用正数 `amount`、幂等 `requestId` 和必填 `remark`；同一广告主与 `requestId` 不允许改变金额或原因。
3. 扣减与点击计费共用 `scx_ocpx_advertiser_account` 行锁，在同一 MySQL 事务中完成余额校验、账户更新和流水写入。
4. 任何扣减都不得使 `available_balance` 小于 0；余额不足时不更新账户、不写成功流水。
5. 成功流水使用 `entry_type=MANUAL_DEBIT` 和正数金额表达方向。流水不可更新、不可删除，保留操作人和原因。
6. 人工扣减不写小时经营指标，不计入广告消费；它只改变可用余额。
7. 使用独立权限 `ocpx:advertiser:deduct`，并在服务层强制真实 `ROLE_ADMIN`。共享 `ROLE_ADVERTISER` 不得获得该权限。
8. 账务类型约束和权限通过前向 V110 SQL 扩展；未应用 SQL 前不得发布调用新接口的后端和前端。

## 结果

- 管理员可以在广告主管理页执行可审计、可重试的余额扣减。
- 并发人工扣减、充值和点击计费在同一账户行上串行化，不会透支。
- 现有消费报表口径保持不变；如未来需要余额流水页面，应读取不可变流水，不能从当前余额反推历史。

## 不在本决策内

- 不实现授信或负余额。
- 不实现流水撤销、编辑或物理删除；纠错应新增反向账务动作并另行决策。
- 不执行生产数据库迁移、真实扣款或发布。
