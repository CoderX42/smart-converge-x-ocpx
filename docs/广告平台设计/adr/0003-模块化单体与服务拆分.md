# ADR-0003 模块化单体与服务拆分

- 状态：Proposed
- 日期：2026-07-14

## 提议

管理面初期采用模块化单体，按 `18-领域边界与数据所有权` 隔离模块；事件接入网关和异步 Worker 可独立部署。M6 的 RTB 网关/决策引擎独立部署。只有出现独立扩容、故障隔离、技术栈或发布节奏证据时再拆分其他服务。

## 约束

- 模块只访问自身表；跨模块通过应用接口或事件。
- 禁止公共“万能 service/dao”绕过边界。
- 即使同库，每张表仍有唯一写入方。
- 拆分前必须有容量/组织/可靠性证据及迁移 ADR。

## 理由

降低一人公司早期部署和调试成本，同时保留未来拆分路径，避免过早微服务化。
