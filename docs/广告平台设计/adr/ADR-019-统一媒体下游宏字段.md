# ADR-019：统一媒体下游宏字段并兼容旧参数

状态：Accepted。2026-09-27 采用方案 B。

## 背景

媒体管理配置的是“媒体 → SCX”的 Feedback 入参。当前页面直接暴露
`caid`、`caid_list`、`caid1`、`caid2`、原值/MD5 等合作方字段，导致新增媒体时
容易重复配置，也让下游监测链接携带了不必要的字段。

## 决策

新建媒体使用 SCX 统一语义字段生成下游监测链接。对于 CAID，新配置默认只生成
`caid=__CAID__`；历史 CAID、第二 CAID 和合作方专用槽位不作为默认下游字段。
Engine 在入站标准化和上游协议适配时兼容旧的 `caid_list`、`caid1`、`caid2`、
`last_caid`、`prev_caid` 字段。不能从当前 CAID 推导的第二值或历史值继续按可选
扩展字段传递，不得静默伪造。

页面以逻辑组合展示原值/MD5、秒/毫秒时间戳等字段，但保存的第一阶段仍使用现有
`macroParams` 查询串格式，以避免数据库迁移。存量媒体配置原样回填和继续生效；
新建配置只生成统一字段。`request_id` 由系统生成并自动加入监测链接，不再作为
可取消的普通宏；`callback_url` 保留为媒体回传字段。

目录外的合作方自定义 `key=宏值` 仍可保存，系统只对 key 格式、重复 key、控制字符
及系统保留字段做校验，避免统一目录阻断真实接入所需的扩展参数。

统一字段只是管理端和下游链接的语义收敛，不代表 Engine 可以从原值自动计算
MD5，也不改变上游 AERIM、微风互动等协议的实际字段名。原值和 MD5 需要媒体按
接入要求分别提供，合作方字段由协议适配器内部映射。

## 兼容与边界

- 旧的媒体 `macroParams` 不迁移、不重写；编辑时识别旧字段并保持原配置。
- 新建媒体的最终查询串不得默认包含 `caid_list`、`caid1`、`caid2`、历史 CAID
  等兼容字段。
- `caid2`、`last_caid`、`prev_caid` 可能携带不同语义，不能由统一 `caid` 自动补齐。
- `mId/tId/aId/lId/event` 是监测任务系统路由字段，不归入媒体宏选择器。
- `impresss_id` 保留现有兼容拼写，界面显示为“曝光 ID（兼容字段）”。

## 验收

- 新建媒体选择 CAID 后，监测链接只出现 `caid=__CAID__`。
- 旧配置含 `caid_list` 或 `caid1` 时，编辑、保存和生成链接均不丢字段。
- 入站请求使用统一 `caid` 时，AERIM/微风适配器仍能按其协议要求完成设备标识映射。
- 原值/MD5、第二 CAID 和历史 CAID 不被错误自动推导。
