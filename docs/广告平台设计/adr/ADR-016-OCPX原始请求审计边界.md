# ADR-016：OCPX 原始请求审计边界

- 状态：Superseded by V122（2026-08-25）
- 日期：2026-08-25

> 本决策因生产磁盘与 MySQL IOPS 放大风险退役；V122 删除全量审计、WAL和管理入口，仅保留 Callback `kid` 密钥环兼容。

## 决策

OCPX 在应用层记录媒体入站、广告主投递、广告主 Callback、计费、媒体扣量和媒体投递六阶段的请求、响应与异常。成功、失败、重复和校验前拒绝均进入独立审计表；现有事实、账务和脱敏流程日志继续作为业务真相。

原文使用 AES-256-GCM 加密保存 30 天，脱敏元数据保存 180 天。根密钥与 Callback 密钥环复用，但使用 HKDF 对 Callback、审计和测试签名进行用途隔离。新 Callback 携带 `kid`，无 `kid` 的存量链接继续按历史密钥顺序读取。

Engine 先写本地加密 WAL，再幂等写 MySQL。MySQL 或 WAL 任一可写时均可恢复；两者同时不可写时业务继续并触发最高级告警和覆盖缺口计数。因此本方案不宣称双故障下绝对零丢失。

只有活动 `ROLE_ADMIN` 且具备专用权限的账号可以解密查看或导出。导出限定单日、最多十万条，使用 HTTPS 流式 ZIP+NDJSON，不生成服务器明文临时文件。

## 后果

- 入口审计表不设置业务外键，以容纳无法解析路由关系的请求。
- 应用看到的 Method、Path、原始 Query、Headers、Body 和 Response 是审计边界；不记录 TLS 包或 Nginx 接收前字节。
- 生产发布必须先评估 MySQL、binlog、备份和 WAL 磁盘容量，并经过真实合作方 UAT。
