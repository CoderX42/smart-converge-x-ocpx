# ADR-003：广告主开户与只读数据范围

- 状态：Accepted
- 日期：2026-08-14

## 背景

vientiane 的广告主新增会同时创建登录账号。SCX 已有 `sys_user.type=2` 和 `shop_id`，但 V102 没有开户入口，也没有 OCPX 行级数据范围；只增加账号和角色会暴露其他广告主数据。

## 决策

1. `scx_ocpx_advertiser.account_user_id` 保存唯一、nullable 的系统用户引用；已有广告主不自动开户。
2. system-api 提供专用开户端口，system-biz 完成用户名唯一校验、BCrypt、`type=2/shop_id=advertiserId`、共享 `ROLE_ADVERTISER` 和用户角色关系。OCPX 广告主服务在同一事务调用该端口。
3. `ROLE_ADVERTISER` 是按角色编码保护的共享系统角色，只授予自身六个只读页面和报表导出，不授予媒体、扣量、充值或写权限。
4. type=2 用户的数据范围只取当前会话 `shopId`；列表、详情、options、Dashboard、报表、CSV、日志和写路径均执行归属检查，缺失范围时 fail-closed。
5. 自助改密只允许当前会话用户，管理员重置保持独立权限；任何响应和日志不得包含原始密码或摘要。

## 结果

开户任一步骤失败都会回滚，不产生孤立用户或广告主。共享角色避免为每个广告主生成角色，但通用角色和用户管理必须禁止编辑、删除或错误分配该托管角色。未来若开放广告主自助运营，应另行评审写权限，并逐接口增加所有权与并发策略，不能只增加前端按钮。
