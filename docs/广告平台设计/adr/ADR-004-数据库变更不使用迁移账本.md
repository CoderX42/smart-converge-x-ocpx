# ADR-004：数据库变更不使用迁移账本

- 状态：Accepted
- 决策日期：2026-08-11
- 决策来源：项目负责人明确要求退役迁移账本及其依赖

## 背景

SCX 已将空库初始化收敛为一份当前态 schema，`init-database.sh` 只允许初始化空库，
不会扫描或自动执行历史增量。已有数据库的结构事实与旧账本记录也可能不一致，继续把
数据库内账本当作版本真相会产生错误判断，并诱导补写历史或重放已执行 SQL。

## 决策

1. 空库只执行 `smart_converge_x_baseline.sql` 及其引用的当前态 schema。
2. 已有库变更只使用经审查的前向增量 SQL，由已授权人员在备份和变更窗口后显式执行。
3. `scx_schema_migration` 退役。当前态 schema、前向增量、回滚/退役脚本和后续业务 SQL
   均不得创建、查询、写入、更新、删除或以其内容作为执行条件。
4. `V{n}__*.sql` 文件名只用于代码组织、审查和发布包识别，不表示数据库内存在对应历史。
5. 发布证据保存在数据库外：Git 提交、SQL 文件 SHA-256、审批与执行记录、目标身份、
   备份证据、`information_schema` 结构后置条件、关键数据对账和数据库校验结果。
6. 已有环境中的旧账本表可以暂时保留，但验证程序不读取它。删除该表是独立的破坏性
   生产操作，必须另行备份、预览和授权。
7. 已执行的历史 `V*.sql` 继续保持不可变；历史文档中的旧账本记录仅作为当时证据，
   不再对当前或未来实现产生约束。
8. CI 和本地质量门必须扫描可执行 SQL，阻止新的账本引用进入仓库。

## 结果

- 数据库版本不能通过单个表或版本号推断，必须核对真实结构、约束、种子和业务数据。
- 前向 SQL 必须具备明确前置条件、后置条件、重复执行策略和失败后的前向修复方案。
- 存量账本记录不补写、不修正，也不作为是否执行某份 SQL 的判断依据。
- 发布清单必须保存数据库外的可审计证据，否则不能把源码或本地门禁描述为目标环境已升级。
