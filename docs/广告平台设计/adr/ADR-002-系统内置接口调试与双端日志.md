# ADR-002：系统内置接口调试与双端日志工作台

- 状态：Accepted
- 日期：2026-08-08
- 范围：V76 / ADX 管理面 / OCPX 数据面

## 背景与约束

SCX 的 OCPX 链路跨管理面、独立引擎、Redis Stream、MySQL 事实、异步投递和 CPC 账务。只发送一个 HTTP 请求或只观察管理面日志，不能证明上下游完整链路有效；直接向浏览器下发渠道密钥、开放任意服务端代理或读取完整日志文件又会扩大 SSRF、密钥和个人信息风险。

完整链路调试可能产生不可撤销的事件、外发、扣量和账务事实。调试工作台因此必须复用正式适配器与可靠投递链路，并把预检、二次认证、一次性授权、关联标识、脱敏、留存和权限作为执行前置条件。

## 决策

- 管理面提供仅管理员可获授权的接口调试页面、共享用例、七天执行历史、结构化执行日志和双端近期日志。
- 已接入模式只选择 `PUBLISHED` 路由并冻结路由版本；真实 URL、方法和适配器不可在页面修改。自定义模式仅允许 HTTPS 443/8443，并执行 DNS 与连接地址双重公网校验。
- 已接入执行复用 `UpstreamAdapter`、`DownstreamAdapter`、正式鉴权、Redis Stream、幂等、扣量、账务、租约、重试与成功判定。适配器只有实现 `AdapterDebugSupport` 后才能合成完整链路请求。
- `debugExecutionId` 贯穿事件信封、事件、callback reference、扣量决策、投递任务、投递尝试和账务流水；Worker 在处理边界恢复 MDC。调试事实不进入常规小时效果报表，真实 CPC 流水仍以 `DEBUG` 来源不可变保留。
- 生产执行使用密码复核、服务端确认短语和绑定用户、会话、IP、草稿的一次性授权；可扣费执行还要求独立按钮权限。
- 管理面调用引擎时不保存长期共享密钥，改为在共享 Redis 中登记 30 秒一次性 HMAC grant；请求携带临时密钥、时间戳和 nonce，引擎使用 `GETDEL` 验证并防重放。该机制不向浏览器暴露任何内部签名材料。
- 原始日志来自每进程有界内存 appender：最多 5,000 条、最近 2 小时、单次最多 500 条，重启不恢复。查询需要五分钟二次授权并写访问审计，公网 Nginx 明确拒绝 `/ocpx/internal/**`。
- 按业务明确接受的例外，用例、请求头、请求体和文本响应在管理员之间明文共享；界面默认遮罩，但这不满足秘密最小化存储，必须持续显示风险提示。

## 候选方案

| 方案 | 优点 | 缺点 | 风险/成本 |
| --- | --- | --- | --- |
| 仅浏览器直连上下游 | 开发量小 | 暴露密钥，受 CORS 限制，不能覆盖异步事实与账务 | 不接受 |
| 单独复制一套调试投递链路 | 容易控制模拟数据 | 与生产行为漂移，重试和成功语义重复维护 | 不接受 |
| 管理面编排并复用正式数据面 | 行为与生产一致，可追踪异步副作用 | 需要严格授权、关联字段和运行隔离 | 接受 |

## 影响

- 数据库新增 V76 调试表，并为 OCPX 事实、投递和账务增加可空关联字段；调试执行与日志七天清理，用例长期保留。
- 管理面增加受限 HTTP 客户端和有界执行器；引擎增加不进入公开 OpenAPI 的内部编排与日志接口。
- 完整链路调试可造成真实扣款与外发；关闭功能开关只能停止后续执行，不能撤销既有事实。
- 双端必须共享可达的 Redis 和 MySQL，且内部入口只能由可信网络访问。

## 迁移、回滚与验证

V76 只做前向新增，不删除或改写既有事实。停用时关闭双端调试开关并保留表和关联字段；恢复需重新启用并重新认证。上线前必须备份数据库、应用 V76、重新打包和重启双端、更新 Nginx、让管理员完全退出后重新登录，并在隔离环境完成双向真实链路与重试验收。生产首次真实扣费调试必须由操作者当次预检和确认，部署流程不得代为执行。

## 被替代关系

本 ADR 不替代 ADR-001；它在管理面与独立 OCPX 数据面边界上增加受控调试编排能力。
