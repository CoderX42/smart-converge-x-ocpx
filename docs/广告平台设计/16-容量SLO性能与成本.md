# 16 容量、SLO、性能与成本

## 1. 待确认的业务输入

在 M0 结束前必须确定：日请求量、峰值 QPS、展示/点击/转化比例、事件平均大小、媒体/DSP 数、报表查询峰值、数据保留期、可用性目标和预算。未确认前只能做可替换假设，不能承诺生产容量。

## 2. 基线假设（仅用于设计）

| 项目 | 初始假设 | 是否确认 |
| --- | --- | --- |
| 展示/点击事件峰值 | 2,000 QPS | 否 |
| 转化峰值 | 100 QPS | 否 |
| RTB 峰值 | M6 前为 0；M6 暂按 5,000 QPS | 否 |
| 事件平均大小 | 2 KB | 否 |
| 原始事件热存储 | 30 天 | 否 |
| 聚合报表 | 至少 2 年 | 否 |

这些数字必须在 `风险依赖与开放问题.md` 中关闭后替换。

## 3. SLO

| 服务 | SLI | 建议目标 |
| --- | --- | --- |
| 管理 API | 成功率 | 99.9%/月 |
| 事件接入 | 非平台错误成功接收率 | 99.95%/月 |
| 事件接入 | P99 响应 | < 100 ms（不含公网） |
| 归因 | 处理新鲜度 | 99% 在 5 分钟内 |
| 回传 | 平台可控成功投递 | 99% 在 15 分钟内 |
| 实时报表 | 数据新鲜度 | 95% 在 5 分钟内 |
| RTB（M6） | 内部 P99 | 低于合作方 tmax 的 70% |

外部合作方故障从平台可用性中分开统计，但必须计入业务体验和告警。

## 4. 容量模型

- 接入带宽 ≈ 峰值 QPS × 平均请求大小 × 协议开销 × 安全系数。
- 消息存储 ≈ 日事件数 × 平均消息大小 × 保留天数 × 副本数。
- 分析存储 ≈ 原始事实 + 聚合 + 索引/副本；压缩率通过样本测试确认。
- 消费能力必须长期高于生产峰值，并能在目标时间内清空计划内积压。
- 分区键避免单一广告主/媒体热点，同时满足必要顺序。

## 5. 压测场景

稳态、阶梯增长、突发峰值、单媒体热点、大 payload、重复事件、下游变慢、消息积压恢复、缓存失效、数据库故障转移、灰度版本混跑。压测必须观察正确性和资金/预算，而不只看延迟。

## 6. 性能护栏

- 高频路径禁止 N+1 查询和不受控外部同步调用。
- 缓存失效应有限流/降级，不能把全部流量压到数据库。
- 报表查询限制时间范围、维度数、基数和导出大小；大查询异步执行。
- 每项资源设置超时、连接池、队列上限和背压；禁止无限队列。

## 7. 成本

按每百万事件的接入计算、消息、热存储、冷存储、分析查询和网络回传成本跟踪。容量扩展需同时给出性能收益和月度成本影响。原始数据保留、日志采样、索引和导出过期策略是主要成本控制点。
