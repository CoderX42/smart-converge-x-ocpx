# SCX OCPX 智能投放技术开发设计

> 状态：Accepted product direction / Incremental implementation
>
> 更新日期：2026-07-27
>
> 事实规则：本文件定义目标和依赖关系；“已实现”只能由当前代码、迁移、测试和运行证据证明。

## 1. 产品边界与锁定决策

SCX 是单企业内部使用的效果广告投放、归因和运营平台，不是多租户广告交易市场。第一阶段采用
媒体托管 OCPX：SCX 管理业务目标、追踪、归因、回传和运营，媒体侧负责竞价与流量分配；暂不
建设 SCX 自有 RTB/DSP 竞价内核。

当前默认业务基线：

- 首个优化事件：`FORM_SUBMIT`。
- 目标成本：CPA 50 CNY。
- 归因：Last Click、7 天窗口、`Asia/Shanghai` 业务时区。
- 商业层级：直客或代理商；代理商下最多一层子代理商；广告账户归属客户。
- 财务：先建设虚拟资金沙箱和双分录账本，不接真实支付、真实开票或自动结算。
- 隐私：不保存或记录原始 IDFA、IMEI、OAID、GAID、IDFV、CAID 或完整外部设备哈希。
- 数据库：只允许前向迁移；已执行版本、脚本名和校验和不可改写。

## 2. 当前架构

后端保持 Spring Boot 模块化单体，统一由 `scx-boot` 部署：

| 模块 | 当前职责 | 状态 |
|---|---|---|
| `scx-subject` | 媒体主体和 `scx_user_subject_scope` 对象授权 | 已实现 |
| `scx-delivery` | 客户、产品、渠道、链接、任务、媒体配置和 RTA 配置 | 已实现基础能力 |
| `scx-tracking` | 渠道凭据、事件入口、去重、归因、回传、Outbox、RTA | 已实现沙箱闭环，生产验收未完成 |
| `scx-reporting` | 日报、维度汇总、明细和异步导出 | 已实现基础能力 |
| `scx-commercial` | 客户/代理商/广告账户/合同/授信 | 未创建 |
| `scx-finance` | 虚拟账户、账本、充值、调账、退款、结算、发票 | 未创建 |
| `scx-inventory` | 媒体、流量位、版位、设备、地域、屏蔽和调度能力 | 未创建 |
| `scx-creative` | 素材、创意、审核、版本和组合 | 未创建 |
| `scx-campaign` | Campaign/AdGroup/Ad、预算、排期、出价和状态机 | 未创建 |

MySQL 保存业务事实与幂等约束；Redis 保存会话、nonce、限流、缓存和可靠 Stream；RocketMQ
承载 Outbox 发布后的异步事件。管理端使用 Vue 3 + Element Plus，并由后端权限与对象范围共同
授权，菜单可见性不构成安全边界。

## 3. R1-00 基础可信边界

R1-00 是所有商业、财务、库存、素材和投放域的前置任务。当前代码切片包含：

- 媒体对象范围：管理员全量；运营仅能读写明确授权媒体；分析员可读不可写；未登录无范围。
- 渠道凭据端点权限：`CLICK`、`CONVERSION`、`RTA`；未知机器接口默认拒绝。
- 回执权限：具备 `CLICK` 或 `CONVERSION` 的渠道可查询本渠道回执。
- 回执可解释性：转化回执返回当前归因状态和原因码，点击回执不伪造归因字段。
- 凭据时钟：签发、轮换和吊销使用数据库 `NOW(3)`，避免应用与数据库时区漂移。
- 密钥注入：开发/生产配置仅引用环境变量；生产主密钥、设备 HMAC、数据源、Redis、MQ、
  XXL-JOB 和登录加密值不得内联。
- 迁移：V43 审计请求字段扩容、V44 端点权限、V45 凭据时钟修复、V46 系统菜单融合。

R1-00 的代码、单元测试、空库/升级迁移和本地构建通过，不等于目标环境验收。以下事项仍是
完成 R1-00 的必要条件：

1. 在受控目标环境应用 V43–V46 并核对迁移账本、权限、菜单和历史数据。
2. 用管理员、运营、分析员、无媒体范围账号完成真实 HTTP/浏览器越权回归。
3. 轮换所有曾进入版本历史的真实凭据，并按安全流程处置历史暴露。
4. 由真实第三方完成签名、端点权限、回执、回传和密钥轮换 UAT。
5. 在独立多实例环境完成 RocketMQ/Outbox 故障恢复及 20k/40k 容量门禁。

上述依赖未满足前，不启动 R1-01，不宣称 R1 完成或生产可接入。

## 5. 核心数据与一致性规则

- 资金变动必须由不可变账本表达，余额是可重建投影；一次业务至少有一借一贷且合计为零。
- 投放对象状态迁移必须有版本、操作者、原因和审计记录；启用配置不能原地覆盖。
- 原始事件、归因结果、回传任务和报表快照分层保存；重算产生新版本，不覆盖历史事实。
- HTTP `202` 仅表示可靠受理；完整成功必须对账 Raw Event、归因、Callback、Outbox、MQ 和
  Redis Pending/DLQ。
- 外部平台错误必须归一为稳定错误码，同时保留脱敏后的原始响应引用用于排查。
- 不存在与无权限的对象统一返回不可区分的结果，避免资源枚举。

## 6. 验收门

每个任务必须同时提供：迁移、后端、前端、契约、测试、运行证据、回滚/前向修复路径和文档。
静态检查、编译、本地沙箱、模拟 UAT、目标环境、真实媒体验收和生产容量是不同证据层级，不能
互相替代。
