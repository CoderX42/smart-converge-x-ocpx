# SCX 管理端开户与数据范围 V103

## 决策

V103 在 V102 页面字段基线上补齐 vientiane 广告主开户语义，同时使用 SCX 现有账号与角色体系，不复制参考系统的硬编码角色 ID 或明文日志行为。

- 新增广告主时名称、请求地址、用户名、密码必填；用户名和密码只在新增弹窗出现。
- 一个广告主最多绑定一个 `sys_user`，已有广告主保持未绑定并在表格显示用户名“—”。
- 共享 `ROLE_ADVERTISER` 是系统托管角色；账号为 `type=2`，`shop_id` 保存广告主主键。
- 广告主账号只读自身的广告主、推广链接、监测任务、Dashboard、报表、CSV 和流程日志；不开放媒体、扣量、充值或增删改。
- 数据范围由后端从会话强制派生，前端筛选条件不能扩大范围。
- 新增弹窗展示名称、请求地址、凭据引用、宏参数、用户名、密码；宏参数默认空且非必填，只有实际填写时才保存。列表展示已配置宏时的最终请求地址。
- 请求地址与宏参数仍分列保存，Engine 发起广告主请求时按 URL 现状自动选择 `?` 或 `&` 拼接、过滤重复 query key，再替换本次反馈的真实宏值。

完整接口字段见 [V103 增量契约](contracts/management-v103.md)，账号绑定与范围决策见 [ADR-003](adr/ADR-003-广告主开户与只读数据范围.md)。

## 数据库与发布

`V103__add_advertiser_account_scope.sql` 给广告主增加 nullable、唯一的 `account_user_id`，创建共享角色和只读菜单关系，并扩展监测 URL 列。该文件是人工审核的前向 SQL，不读取或写入退役迁移账本，也不自动应用到现有环境。

发布前必须备份目标库，确认当前结构已完成 V102，核验 SQL SHA-256，再执行 V103 并运行 `verify-database.sh`。源码测试或隔离数据库成功不等于目标数据库、宝塔部署、服务重启或真实协议 UAT 完成。

## URL 风险

为保持当前参考兼容，管理面允许任意 scheme、本机和内网 URL。广告主请求地址会成为 Engine 出站目标，因此存在 SSRF、内网访问和协议误配风险；上线审批必须把它作为已接受风险单列，不能沿用 V102 文档中的“已统一阻断”结论。
