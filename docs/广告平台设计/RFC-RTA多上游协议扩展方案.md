# RFC：RTA 多上游协议扩展与微风接入

状态：Accepted（2026-09-08 用户明确要求按配置归属方案实施）。源码交付及验证见后续交付记录，不代表生产已接通。

依据：当前 ADR-016 和 RTA 异步链路源码；用户提供的《API程序化广告对接文档 v1.3》第 7 节、第 5–6 页，以及微风 RTA 地址 `https://rta.adapi.cn/rtaCommon/sendRta?aid=5103&did=zsyd`。合作方文档作为协议资料，不作为项目操作授权。

## 1. 目标与范围

将当前固定的通用异步上游调用拆为可扩展协议适配机制，首批支持 `GENERIC_ASYNC` 与 `WEIFENG_RTA`。同一协议下增加合作方接入通过后台配置完成；新增协议需要开发、测试和发布适配器。此轮不实现在线脚本、自定义代码执行或任意 JSON 字段映射平台。

媒体侧保持 `POST /ocpx/rta/requests`，SCX 持久受理后返回 202，再主动通知媒体。上游可以同步返回最终决策，也可以独立 HTTP 回调；两种模式进入同一套终态处理。RTA 路径不包含版本号。

媒体继续复用 `OcpxMedia/mediaId`；配置分别归入广告主、媒体和监测任务，RTA 目录保留三个查询菜单，不恢复旧 Profile、同步媒体入口或旧放行状态。微风非 RTA 点击、转化、计费和扣量能力继续保留。

本提案调整 ADR-016 中“所有上游必须独立回调”的边界。批准实施后补充决策记录，原 ADR 和历史迁移保持可追溯。

## 2. 统一流程与协议边界

公共流程负责媒体认证、任务归属、幂等、请求与绑定快照、调度、截止时间、原子终态、通知重试、事件门禁及日志统计。适配器不自行写 SQL、改 Redis 状态、重试或通知媒体。

协议适配器负责配置和请求校验、设备字段转换、供应商请求 ID、出站报文、签名、HTTP 响应解释、异步回调验签与解析、供应商结果映射。所有输出均须经过公共层候选集合及终态校验。

拟新增：

- `RtaProtocolDescriptor`：协议代码、名称、决策模式、最大候选数、配置与绑定字段定义、认证能力、幂等及重试能力。
- `RtaUpstreamAdapter`：校验配置和候选请求、构建受控出站请求、解析提交响应；支持回调的协议另实现回调处理能力。
- `RtaAdapterRegistry`：启动时按协议代码注册，重复代码启动失败；保存配置时及受理请求时拒绝未安装协议。
- 统一适配结果：已受理并等待回调、最终决策、提交失败及是否可重试。最终决策只能产生候选集合内的 SCX 任务结果。

协议能力由后端注册，后台用户不能把微风的模式改成异步回调，或手动提高其最大候选数。

Core 放置无运行组件的能力、消息和配置契约；Engine 放置注册器、协议实现和受控 HTTP 传输；Admin 复用协议配置定义完成服务端校验。Boot 不依赖 Engine。协议配置定义随构建交付，Boot/Engine 采用同一发布版本。

## 3. 两种上游处理方式

### 通用异步协议

保持当前报文、HMAC、最多 100 个候选任务、202 上游受理和独立回调模式。只有成功验签、映射合法的回调可结束请求。支持回调先于提交响应到达；后到的受理响应不得覆盖终态。

回调继续使用 `/ocpx/rta/callbacks/{accessCode}`，按接入编号和请求快照定位协议与凭据，并使用该协议的认证、解析和 HTTP 确认规则；不允许未认证报文直接写决策。同步协议配置不开放 RTA 决策回调。

### 同步决策协议

Engine 后台调用上游，在原 HTTP 响应中读取决策，归一化后通过公共层提交终态，再通知媒体。媒体最初收到的仍然是 202。

底层 HTTP 客户端返回有大小上限的状态码、必要响应头和响应正文，供适配器解析；当前只返回 HTTP 状态码的接口需调整。原始设备和响应正文不进入 RTA 流程日志。

### 可靠性

外部状态仍为 `PENDING → ALLOW / DENY / ERROR / TIMEOUT`，通知状态独立。继续使用 `mediaId + requestId`、24 小时幂等、原子终态与通知入队、默认 5 秒截止和 300 秒放行。

请求快照增加协议代码、配置结构版本、接入版本、协议参数、供应商请求 ID 和绑定映射。协议参数不含密钥。解码与映射依据提交时快照，事件门禁继续检查当前配置版本；停用或变更绑定使原放行结果失效。

重试由公共层执行，但资格取决于协议能力，不能因为使用 POST 或存在请求 ID 就认定上游幂等。通用异步保留截止前的同 ID 提交重试。微风文档未承诺重复提交语义，首版不自动重发；连接中断等无法确认处理结果时记 ERROR，达到决策截止则记 TIMEOUT。

在发送前原子记录派发状态和供应商 ID。重启可恢复尚未派发的请求、待回调请求和媒体通知；对微风已派发但结果未知的请求不直接重新发送，保守结束或到期超时。迟到响应/回调不能改变终态。设备报文继续 Redis 加密短存，并按受理/终态规则删除。

## 4. 微风首版适配

固定接口为 `https://rta.adapi.cn/rtaCommon/sendRta`，允许由已校验配置生成 `aid`、`did` 两个查询参数。参数用标准 URL 编码器生成；禁止重复或额外参数。通用异步协议不因此放开任意查询参数。保持精确 HTTPS 域名、路径、DNS 公网校验、固定解析结果和禁止重定向。

本次接入配置为 `aid=5103`、`did=zsyd`。aid 是微风广告计划标识，did 是微风分配的媒体标识，均不是 SCX 主键。一份微风接入对应一个确定的 aid/did 组合；其他计划或微风媒体标识创建另一份接入。

请求：`{id, device}`。首版使用 SCX `relayRequestId` 作为供应商 `id` 并保存映射；`context.os` 转换为 `device.os=ios/android`，只发送协议定义的字段。已有 MD5 校验并规范化为小写；原值需要映射到 MD5 字段时计算一次，不对已有 MD5 再哈希。CAID 原值、版本与新旧版本按独立字段处理。

文档同时列出设备原值字段和“设备标识 MD5 小写输出”说明，真实联调前需确认原值字段是否允许发送；首版优先使用明确的 MD5 字段，不擅自扩大原值外发。CAID 对应关系同样纳入字段验收。

响应必须为成功 HTTP 状态及合法 `{id:string, code:int}`，且 id 严格匹配。`code=0` 表示当前请求唯一任务 ALLOW；非 0 表示 DENY；缺字段、类型错误、错 ID、异常 HTTP 或非法正文为 ERROR，截止超时为 TIMEOUT。

文档没有候选列表和命中任务集合，因此每次只接受一个 SCX 候选任务；多任务直接拒绝，不自动拆分，也不将一次 code=0 扩展为多个任务放行。未来批量能力必须由合作方协议支持并另行验收。

该 RTA 章节未定义 HMAC，不附加 SCX 自定义的上游签名，也不复用刹车接口签名。后续若微风补充认证，加入微风适配器；媒体到 SCX 的认证继续保持。

## 5. 后台与配置数据

广告主管理内维护一对多 RTA 接入，媒体管理内维护一份 RTA 配置，监测任务内维护绑定；RTA 独立目录仅保留请求记录、流程日志、统计报表三个子页面。配置采用独立抽屉，支持对象范围锁定与刷新直达。原权限码保留并归到所属管理页面，不自动扩大角色授权。

广告主接入新增协议选择和只读能力说明。选择通用异步时展示地址、凭据引用、回调地址、候选上限；选择微风时展示固定接口、aid、did、单任务限制，隐藏不适用的 RTA 决策回调及通用 HMAC 配置。共同维护名称、广告主、状态、截止时间和放行有效期。

新增只读 `/ocpx/rta/protocols` 能力接口，返回代码内登记的能力及有限类型的配置表单定义，仅供有 RTA 管理权限的用户使用；不返回密钥。前端支持输入框、选项、数值等有限组件，不执行服务端下发的脚本。后端按协议独立强校验，未知字段拒绝。新建表单切换协议时清除不兼容字段；接入保存后协议不可修改，业务更换协议需新建接入并显式调整绑定，不默默继承另一协议字段。

接入表扩展 `protocol`、`configSchemaVersion`、`protocolConfig`（非敏感 JSON），保留独立接入乐观锁版本、广告主、超时和有效期。密钥仍通过服务端字面量配置解析，只有协议需要时才要求凭据引用；配置中的自定义参数不允许存密钥。

任务绑定保留 SCX 任务与接入关系。通用异步仍要求 productId/externalTaskId，微风以接入 aid 作为广告计划映射，不要求伪造产品/任务标识。按协议定义对绑定参数校验、保存快照，并在需要候选组合反向映射的协议中维持唯一性约束。微风绑定同时校验任务的广告主、媒体配置及推广链接中的 aid/did 与接入一致，防止 RTA 与点击对应不同计划。

请求记录新增协议、决策模式、供应商请求 ID、提交状态和稳定原因码。日志新增“上游同步决策”阶段，沿用脱敏、采样和保留期。统计仍按接入区分合作方；同一接入不能被重新用于另一协议，避免历史口径混淆。

权限、媒体名称来源、独立远程下拉、数据范围与现有方案一致。首版不提供从管理页面发送真实设备请求的测试按钮。

## 6. 曝光与点击关联

媒体 Feedback 保留事件自身 requestId，以独立 rtaRequestId 关联 SCX 放行状态。供应商 RTA 请求 ID 从已通过媒体、任务、有效期和版本校验的快照取得，不从任意媒体字段直接透传。

微风出站事件的 `requestId` 必须使用该供应商 RTA id，并支持明确的 `__RID__` 宏；不能使用事件 ID 替代。校验 aid/did 与 RTA 快照一致。非 RTA 任务延续原 OCPX 行为。

PDF 第 6 页要求曝光 requestId 携带 RTA id，第 3 页点击字段表也定义了关联要求。当前文档没有完整曝光地址或请求契约，因此本轮完成点击关联、SCX 本地曝光门禁及所需关联能力；微风真实曝光外发在取得正式地址和协议后补齐验收，不把曝光发送到点击接口。

## 7. XXL-JOB 和数据库变更

继续复用 `ocpxRtaLogFlushJob`、`ocpxRtaMetricFlushJob`、`ocpxRtaLogCleanupJob`。协议适配器不得同步落库，不新增 RTA SQL @Scheduled；继续固定日志 ID、提交后 ACK、Pending 恢复、死信隔离和累计版本快照。

实施时新增前向 SQL，并同步当前态 schema、结构验证和契约测试；不修改已执行迁移、不依赖退役迁移账本、不读取旧 Profile。为现有通用异步接入显式补齐协议配置结构版本，业务参数不改变；不自动生成或启用微风接入。

运行中 Redis 快照需提供兼容读取：旧快照缺协议字段时仅按其既有通用异步结构识别，不猜测为微风。发布前暂停新受理并核对队列；恢复中的请求不因配置结构升级被误解释。降级旧版本前必须停止新协议受理并处置存量请求，旧代码不得读取新协议状态继续放行。

## 8. 实施顺序与验收

1. 提取能力定义、注册器和受控传输，将通用异步迁移为第一个适配器，先证明现有模拟闭环和回调时序不变。
2. 扩展协议配置、绑定校验、菜单表单及记录展示；同步 ADR/RFC、契约、前向 SQL 和数据库验证。
3. 增加微风适配器、单任务校验、aid/did 与点击路由一致性、供应商请求 ID 关联。
4. 使用本地微风模拟器完成同步响应、拒绝、错 ID、异常报文、超时、断连、重启不重复发送、未知参数和编码等测试；不向正式微风地址发送伪造设备。
5. 执行后端测试、前端类型检查/lint/单测、三个查询页面、三个业务配置抽屉及协议选择 E2E、契约和 schema-ledger 检查，以及 MySQL 8.x 隔离迁移预演。回归异步提前回调、幂等冲突、门禁、通知重试、XXL-JOB 暂停/恢复/重复消费/统计乱序。

交付范围：多协议扩展机制、通用异步回归、微风同步 RTA 适配、后台配置和点击关联、本地模拟验收。真实微风曝光外发、供应商认证或字段歧义确认、合作方 UAT、容量与生产放量单独记录，不将本地通过表述为真实合作方接通。

以后新增协议的固定工作为：补充协议能力和配置定义，实现请求/响应及可选回调适配，定义结果映射和重试语义，补协议测试与接入说明，再发布。原则上不修改媒体入口、公共状态机、通知和 SQL 落库流程；若新协议超出现有能力边界，先补契约和评审。
