## 一、系统定位与角色体系

### 1.1 系统类型
- **ocpx.aerim.cn** 是一个 **OCPX（Optimized Cost Per X）广告效果监测与归因平台**，服务于广告主与媒体之间的效果追踪、数据回传和结算对账。
- 核心功能围绕：上游客户管理、推广链接管理、投放任务配置、全链路数据归因报表。

### 1.2 目标用户
- **广告主/上游客户**：创建推广链接、配置监测任务、查看转化数据
- **媒体/渠道方**：接入任务链接、回传设备行为数据
- **运营/平台管理员**：审核链接、管理客户、查看平台大盘数据

### 1.3 角色体系与权限差异（基于 llf 账号可见范围）

| 角色维度 | 可见菜单 | 权限差异观察 |
|---------|---------|------------|
| **当前账号（llf）** | 客户管理、链接管理、任务管理、数据管理（任务汇总） | 完整操作权限（新增、编辑、搜索、导出） |
| **系统管理**（面包屑有但菜单无） | 上游客户管理管理 | 推测该角色拥有更高层级菜单（如租户、用户、角色管理） |
| **广告主角色** | 可能仅可见自己创建的链接和任务 | 未验证（需独立账号测试） |
| **媒体角色** | 可能仅可见接入的渠道和回传配置 | 未验证（需独立账号测试） |

> **观察**：当前系统采用**单层级扁平菜单**，左侧仅 4 个一级菜单 + 1 个子菜单。系统管理功能未在当前角色菜单中展示，但面包屑暴露其存在，说明存在**基于角色的菜单权限控制（RBAC）**。

## 四、技术观察

### 4.1 前端框架/组件库推测
- **前端框架**：Vue 3（通过 `__VUE_DEVTOOLS_ROUTER__` 确认）
- **组件库**：TinyVue（华为开源 Vue 组件库，通过 DOM 类名 `tiny-tree-node`、`tiny-input__inner`、`tiny-form-item__label` 确认）
- **UI 风格**：蓝白配色，左侧树形菜单，顶部面包屑，卡片式内容区，与 Element Plus 类似但使用 TinyVue
- **布局**：经典 Admin 布局（Header + Sidebar + Content），响应式支持

### 4.2 图表库
- 仪表盘暂未观察到图表（仅为数字卡片），但报表页预计使用 **ECharts**（行业标配）
- 建议 SCX 使用 **ECharts** 或 **AntV G2Plot** 进行漏斗图、趋势图、留存曲线展示

### 4.3 文件上传/预览方式
- 当前未观察到文件上传功能（链接地址、下载地址为文本输入）
- 建议 SCX 在需要时集成阿里云 OSS 上传组件（已在技术栈中）

### 4.4 权限控制模式
- **当前系统**：RBAC（基于角色的访问控制）
  - 菜单级权限：不同角色展示不同菜单（当前 llf 可见 4+1 菜单，系统管理菜单被隐藏）
  - 操作级权限：表格操作按钮（编辑/禁用）对所有可见数据生效
- **SCX 建议**：
  - 采用 **RBAC + 数据范围权限**（如广告主只能看自己的数据）
  - 服务端必须校验数据归属（`owner_id` / `tenant_id`）
  - 菜单权限通过后端返回的动态路由配置

### 4.5 与 SCX 技术栈的差异点

| 维度 | ocpx.aerim.cn | SCX 技术栈 | 差异/建议 |
|------|----------------|-----------|-----------|
| 前端组件库 | TinyVue | Vue 3（未指定组件库） | 建议评估 TinyVue vs Element Plus vs Ant Design Vue |
| 后端框架 | 未确认（可能是 Node.js/Python） | Spring Boot 3.x | SCX 使用 Java 生态，更适合企业级广告平台 |
| 缓存 | 未确认 | Redis | 一致 |
| 消息队列 | 未确认 | RocketMQ | 一致，建议使用 RocketMQ 处理归因事件流 |
| 分析库 | 未确认 | Druid | 一致，Druid 适合实时广告归因分析 |
| 对象存储 | 未确认 | 阿里云 OSS | 一致，用于导出文件、素材存储 |
| 数据库 | 未确认 | MySQL 8.x | 一致，建议主从分离，报表查询走只读副本 |
| 权限控制 | RBAC（菜单+操作） | 待实现 | 建议 SCX 增加数据范围权限 |

### 5.2 核心难点及应对思路

| 难点 | 描述 | 应对思路 |
|------|------|----------|
| **实时归因计算** | 日点击 1.5 亿级，需要毫秒级点击-激活匹配 | Druid 预聚合 + Redis 缓存热点数据；归因窗口（如 7 天）用异步任务补偿 |
| **设备去重** | 同一设备多次点击/激活，需要去重和计费 | 基于设备 ID（IDFA/IMEI/OAID）的布隆过滤器 + Redis Set 去重 |
| **多维度报表聚合** | CPA、Daily、产品、任务、渠道、运营多维度交叉 | Druid 实时 OLAP + 预计算 Cube；报表查询走只读 Druid 集群 |
| **事件回传可靠性** | 回传失败需重试，避免重复回传 | RocketMQ 事务消息 + 幂等校验（msg_id + 业务 key） |
| **数据安全与合规** | 设备 ID、用户行为数据属 PII | 字段分级加密；数据脱敏展示；保留期策略；访问审计日志 |
| **并发导出性能** | 大数据量导出可能阻塞 | 异步导出任务队列；OSS 文件存储；下载链接有效期控制 |

### 5.3 与现有 ADR-0002 基线的对齐/冲突点

| ADR-0002 基线 | 对齐/冲突 | 说明 |
|--------------|----------|------|
| Java 17 + Spring Boot 3.x | ✅ 对齐 | 后端使用 Java 生态，适合高并发广告平台 |
