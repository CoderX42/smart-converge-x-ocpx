# 18 领域边界与数据所有权

## 1. 领域规则

每张业务表只有一个写入模块；其他模块通过公开 API、查询投影或领域事件访问，禁止跨模块直接更新表。模块化单体也必须遵守此规则，以便未来按负载拆分而不重写业务语义。

## 2. 限界上下文

| 上下文 | 聚合根 | 负责 | 不负责 |
| --- | --- | --- | --- |
| IAM | User、Role、ServiceCredential | 身份、角色、权限、会话、服务凭据。 | 广告主余额、投放状态。 |
| 主体管理 | Advertiser、Publisher | 商业主体、资质、主体状态和归属。 | 用户登录、账务流水。 |
| 需求投放 | Campaign、AdGroup、Ad、Creative | 投放层级、预算声明、定向、频控、素材版本。 | 最终资金入账、媒体库存。 |
| 供给库存 | App/Site、Placement | 媒体资产、广告位、格式、底价、接入配置。 | 选择广告、广告主合同。 |
| 审核风控 | ReviewCase、RiskCase | 审核结论、风险规则、证据、处置和申诉。 | 修改投放正文、删除事件。 |
| 事件追踪 | RawEvent、Touchpoint | 事件接收、验签、去重、标准化和触点。 | 决定归因获胜触点、记账。 |
| 归因回传 | Attribution、CallbackDelivery | 归因、回传映射、重试、死信和撤销。 | 修改原始事件或媒体配置。 |
| 预算计费 | BudgetCounter、BillingFact | 预算校验/预占、可计费事实和价格版本。 | 广告主充值、结算支付。 |
| 账务结算 | FinancialAccount、LedgerEntry、Statement | 资金流水、余额、账单、对账、冲正和结算。 | 判断点击/转化有效性。 |
| 数据报表 | FactProjection、AggregateReport | 消费事实、聚合、查询、导出和重述版本。 | 作为账务事实源。 |
| 实时交易（M6） | Auction、Decision | 请求、候选、过滤、排序、竞价和广告响应。 | 修改归因、账单或历史配置。 |

## 3. 数据所有权

| 数据/表族 | 唯一写入方 | 可读方 | 变更通知 |
| --- | --- | --- | --- |
| users/roles/credentials | IAM | 管理 API、审计 | identity.* |
| advertisers/publishers | 主体管理 | 投放、库存、财务 | subject.* |
| campaigns/ad_groups/ads/creatives | 需求投放 | 发布、交易、报表 | delivery.* |
| apps/placements | 供给库存 | 发布、交易、报表 | inventory.* |
| raw_events/touchpoints | 事件追踪 | 归因、报表 | tracking.* |
| attributions/callback_deliveries | 归因回传 | 计费、报表 | attribution.* / callback.* |
| budget_reservations/billing_facts | 预算计费 | 财务、报表 | billing.* |
| accounts/ledger/statements | 账务结算 | 财务 API、报表投影 | finance.* |
| aggregate_reports | 数据报表 | 报表 API | reporting.* |

## 4. 允许的依赖

- 管理面可同步查询主体、IAM 和当前配置；跨域写操作使用领域命令/API。
- 高频事件链路通过本地缓存和消息通信，不在请求路径同步调用账务或报表。
- 账务只消费已确认、幂等的计费事实，不直接读取原始事件判断有效性。
- 报表可读取投影/消息，不能反向修改领域事实。
- 风控可发布“限制/解除”决定，由所属领域执行合法状态迁移。

## 5. 业务不变量

- 已发布投放版本不可原地改写；修改产生新版本。
- 创意版本一版一行，审核结论绑定具体版本。
- Placement 所属 App/Site 必须与 Publisher 一致。
- 同一外部事件在同一来源作用域内只有一个有效事实。
- 一条转化在同一广告主作用域内最多一个当前有效归因；撤销与重算保留历史。
- 每个可计费事实最多对应一组幂等账务分录。
- 关闭账单不可修改，只能追加冲正或补差。

## 6. 一期到 M6 的演进

一期由投放中心发布静态绑定与追踪令牌，事件追踪建立触点。M6 新增实时交易上下文产生 request/auction/decision 和追踪令牌；其下游仍通过标准事件进入事件追踪，不获得跨域写权限。
