# 13 测试策略与需求追踪

## 1. 质量目标

测试的核心不是覆盖率数字，而是证明权限不串、事件不丢不重、归因可解释、预算不超、账务可平、协议可兼容、故障可恢复。

## 2. 测试层级

| 层级 | 范围 | 必须覆盖 |
| --- | --- | --- |
| 单元 | 纯规则和领域对象 | 状态机、金额、预算、定向、去重、归因、重试分类。 |
| 组件 | 单服务 + 真实依赖容器 | 数据库约束、Redis 原子操作、Outbox、消息幂等。 |
| 契约 | 提供方/消费方 | OpenAPI、事件 schema、Webhook、媒体适配器样例。 |
| 集成 | 多模块闭环 | 投放发布、事件到归因、回传、报表、记账。 |
| E2E/UAT | 用户流程 | 从建投放到对账结算的真实角色操作。 |
| 非功能 | 系统质量 | 性能、容量、故障、安全、恢复和数据修复。 |

## 3. 高风险测试矩阵

| 风险 | 场景 |
| --- | --- |
| 越权 | ID 猜测、批量接口、导出、缓存、异步任务、审计查询。 |
| 重复 | HTTP 重试、消息重复、消费者重启、死信重放、并发请求。 |
| 乱序/迟到 | 转化先于点击到达、跨日迟到、配置版本变化后补数。 |
| 金额 | 精度边界、并发扣费、冲正、日切、账单关闭、余额不足。 |
| 配置 | 灰度中节点版本不一、回滚、旧令牌、旧密钥。 |
| 外部故障 | 超时、断连、429、5xx、慢响应、错误证书和异常大响应。 |

## 4. 测试数据

- 使用合成、脱敏、可复现的数据工厂，禁止复制生产 PII 到开发环境。
- 每个外部协议维护成功、失败、边界、旧版本和恶意样例。
- 金额测试覆盖 0、最小单位、舍入边界、上限、负向冲正和溢出。
- 时间测试固定时钟，覆盖时区、日切、闰日和夏令时（若业务地域涉及）。

## 5. 质量门

| 阶段 | 通过条件 |
| --- | --- |
| 提交 | 格式/静态检查、受影响单测、秘密扫描。 |
| 合并 | 组件测试、迁移测试、契约兼容、关键路径覆盖。 |
| 预生产 | E2E、性能基线、安全扫描、可观测性和回滚演练。 |
| 生产灰度 | 核心指标、错误预算、数据对账、无严重告警。 |
| 里程碑验收 | 需求追踪矩阵完整、证据可访问、已知限制已登记。 |

账务、权限、归因和幂等核心代码不允许以“时间紧”为由跳过自动化测试。

## 6. 验收证据

每项需求在 `需求追踪矩阵.md` 中关联测试 ID。证据至少包含：测试版本/提交、环境、数据集、操作/命令、期望、实际结果、日志或报告路径、执行日期。截图只能作为 UI 补充，不能替代接口和数据证据。

## 7. 缺陷等级

| 等级 | 例子 | 发布规则 |
| --- | --- | --- |
| P0 | 丢数据、重复扣费、跨主体泄露、无法回滚。 | 立即阻止/回滚。 |
| P1 | 核心链路失败、账单不平、归因大面积错误。 | 不得发布。 |
| P2 | 有规避方案的非核心功能错误。 | 评估并记录风险。 |
| P3 | 文案、低影响体验问题。 | 可排期。 |

## 8. Definition of Done

需求、设计、代码、数据库迁移、API/消息契约、权限、测试、可观测性、回滚和文档同步全部完成，且无未披露限制，任务才可标记“已验收”。“代码写完”不等于完成。
