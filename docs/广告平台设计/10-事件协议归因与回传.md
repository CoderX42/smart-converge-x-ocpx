# 10 事件协议、归因与回传

## 1. 一期与 RTB 阶段边界

一期不要求平台进行实时广告选择。投放系统生成带有 `campaign/ad_group/ad/creative/media/placement` 标识的签名追踪链接或参数，媒体/广告主使用这些标识上报展示、点击和转化。M6 加入 OpenRTB 后，`request_id`、`auction_id` 和素材响应由实时交易引擎生成，但下游事件、归因和账务模型保持兼容。

## 2. 标准事件信封

```json
{
  "schemaVersion": "1.0",
  "eventId": "evt_01...",
  "eventType": "CLICK",
  "source": "MEDIA",
  "sourceId": "pub_123",
  "occurredAt": "2026-08-01T08:00:00.123Z",
  "sentAt": "2026-08-01T08:00:00.456Z",
  "requestId": "req_optional",
  "impressionId": "imp_optional",
  "clickId": "clk_123",
  "trackingToken": "opaque_signed_token",
  "device": {"oaidHash": "...", "idfaHash": "...", "ip": "...", "ua": "..."},
  "properties": {}
}
```

事件信封字段有严格白名单和长度限制；`properties` 只承载已登记扩展，禁止无边界透传。

## 3. 事件处理状态

`RECEIVED → VERIFIED → DEDUPED → NORMALIZED → ATTRIBUTED/NOT_ATTRIBUTABLE → BILLABLE/NON_BILLABLE → CALLBACK_PENDING → COMPLETED`

任一阶段失败进入 `REJECTED` 或 `QUARANTINED`，保存标准原因码。接收接口返回成功只代表 `RECEIVED`，不代表有效、归因或计费成功。

## 4. 幂等与去重

| 事件 | 首选幂等键 | 备用键 |
| --- | --- | --- |
| 展示 | `source_id + impression_id` | 追踪令牌 + event_type + 受控时间桶 |
| 点击 | `source_id + click_id` | 追踪令牌 + event_type + 受控时间桶 |
| 转化 | `advertiser_id + conversion_id` | 广告主 + 业务事件 + 外部订单哈希 |
| 回传 | `target + attribution_id + event_type + rule_version` | 不允许无键发送 |

备用键只能在对应接入协议明确约定时启用，不能用设备 ID + 分钟桶粗暴去重所有用户行为。

## 5. 追踪令牌

令牌承载或引用广告主、投放层级、媒体、广告位、生成时间、随机数和版本。采用服务端密钥签名；对外呈现为不透明字符串。令牌不能包含可直接读取的手机号、原始设备号或内部密钥。支持密钥版本和轮换。

## 6. 一期归因规则

1. 校验转化签名、事件 ID、事件时间和转换类型。
2. 若有可信 `click_id`，优先精确查找点击触点。
3. 无精确标识时，只在协议允许的设备/业务标识范围内查找候选触点。
4. 过滤转化前发生、超归因窗口、风控拒绝和不可投放触点。
5. 默认采用最后一次有效点击；无点击且配置允许时采用最后一次有效展示。
6. 保存归因模型、规则版本、窗口、候选数、获胜触点和拒绝原因。

默认窗口是产品初始值而非永久标准：点击 7 天、展示 1 天。实际值由已发布配置决定。

## 7. 转化类型

| 代码 | 含义 | 是否允许价值 |
| --- | --- | --- |
| ACTIVATE | 首次激活 | 否 |
| REGISTER | 注册 | 否 |
| LOGIN | 登录 | 否 |
| LEAD | 有效线索 | 可选 |
| ORDER | 下单 | 是 |
| PAYMENT | 付费成功 | 是 |
| RETENTION | 留存事件 | 否 |
| CUSTOM | 已登记的自定义事件 | 按登记配置 |

自定义事件必须先登记事件代码、字段、计费资格、回传映射和数据保留级别。

## 8. 回传任务

- 归因成功后按媒体回传映射生成不可变任务快照。
- 密钥、URL、事件映射采用任务创建时的配置版本；密钥泄露等安全事件可强制切换。
- 重试采用指数退避加抖动；明确区分可重试网络/5xx、限流和不可重试 4xx/协议错误。
- 每次尝试保存时间、响应码、耗时、脱敏摘要和 trace_id。
- 超过阈值进入死信；重放保持同一幂等键。

## 9. 数据修复

禁止直接修改原始事件或归因结果。修复通过新建修复批次、追加更正事实、重算受影响聚合及必要的资金冲正完成。所有修复提供 dry-run 差异报告。

## 10. 契约验收场景

- 重复、乱序、延迟、缺字段、错误签名和旧 schema 事件。
- 点击发生在转化之后、超窗口、多个候选触点、重复 conversion_id。
- 回传超时、429、5xx、不可重试 4xx、密钥轮换和死信重放。
- 事件总线重复投递、消费者重启和同一分区乱序保护。
