# 15 部署、运维、灾备与 Runbook

## 1. 环境

| 环境 | 用途 | 数据规则 |
| --- | --- | --- |
| local | 单机开发和组件测试 | 全合成数据。 |
| test | 自动化集成和契约测试 | 可重置合成数据。 |
| staging | 生产等价验证、压测与演练 | 脱敏或专用测试数据。 |
| production | 真实业务 | 严格权限、审计和变更控制。 |

环境配置同构，密钥和容量不同。禁止共享数据库、消息主题、对象存储桶或密钥。

## 2. 部署单元

初期可采用模块化单体管理面 + 独立事件网关/消费者，按负载和可靠性再拆分。无论部署形态如何，领域边界、消息契约和数据所有权保持稳定。

每个部署单元必须提供：启动/就绪/存活检查、版本信息、指标、结构化日志、优雅关闭、资源限制、配置校验和回滚镜像。

## 3. 可观测性

- Trace：接入请求、事件、归因、回传、计费、报表关联同一 trace/业务 ID。
- Metrics：QPS、延迟、错误、限流、积压、消费延迟、去重、归因、回传、预算、账务不平和数据新鲜度。
- Logs：结构化、脱敏、含版本/环境/trace，禁止默认记录敏感 payload。
- Audit：与运行日志分开，满足更长保留和防篡改要求。

## 4. 备份与恢复

| 数据 | 备份 | 恢复验证 |
| --- | --- | --- |
| 交易数据库 | 全量 + 增量/PITR | 每季度恢复演练。 |
| 消息 | 多副本 + 足够保留期 | 验证重放和消费者位点。 |
| 分析数据 | 副本 + 原始事件可重建 | 定期抽样重算。 |
| 素材/导出 | 对象版本、生命周期策略 | 校验哈希与访问权限。 |
| 配置/密钥引用 | 版本化备份 | 验证回滚与轮换。 |

一期目标 RPO ≤ 5 分钟、RTO ≤ 1 小时，最终值由容量 ADR 确认。

## 5. 通用事故流程

发现 → 分级 → 指定负责人 → 控制影响 → 保留证据 → 恢复 → 校验数据 → 对外/内部通报 → 复盘与行动项。事故中禁止未经记录直接改库。

## 6. 核心 Runbook

### 6.1 事件积压

检查生产速率、消费速率、分区倾斜、下游数据库和失败重试；先保护接入，再扩容消费者；若坏消息阻塞，隔离到 DLQ；恢复后核对事件数量与报表水位。

### 6.2 回传失败激增

按媒体、响应码和版本聚合；确认外部故障、密钥、签名、DNS/证书或协议变化；暂停无效重试避免放大；修复后用原幂等键分批重放。

### 6.3 账务不平

立即阻止相关账单关闭/结算；冻结自动调整；对比计费事实、流水、余额快照和消息幂等；通过冲正/补记修复，禁止覆盖历史。

### 6.4 错误配置发布

停止继续扩散，回滚到上一已知良好版本；确认节点收敛；评估期间产生的投放、事件和费用；必要时启动数据修复批次。

### 6.5 密钥泄露

紧急撤销/轮换，限制来源，检查审计和异常调用，评估敏感数据影响，通知负责人；旧密钥不可因兼容性继续无限有效。

## 7. 事故复盘

使用模板记录影响、时间线、根因、促成因素、检测缺口、处置、数据/资金校验、长期行动项和负责人。复盘关注系统改进，不以个人归责替代技术措施。
