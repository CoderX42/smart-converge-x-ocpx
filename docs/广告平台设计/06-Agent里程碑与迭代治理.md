# 06 Agent 里程碑与迭代治理

> 本文件是后续 Agent 实施 **Smart Converge X（SCX）/ 瑶知智汇广告平台** 的唯一长期研发导航文件。它与 `01` 至 `05` 共同构成产品基线；发生冲突时，先服从明确的用户新指令，其次服从本文件的系统边界和验收门。

## 1. Agent 启动协议

每个新 Agent 在开始任何设计、编码、迁移或部署前，必须按以下顺序工作：

1. 阅读本文件与 `README.md`，确认当前里程碑和未关闭风险。
2. 阅读与当前任务对应的需求、业务规则、架构、数据和安全文档。
3. 仅检查与任务相关的现有实现、数据库迁移、接口和测试；不得默认重构整个系统。
4. 输出“本次目标、影响范围、不做什么、验证方式”。涉及数据模型、事件、账务、归因、权限或外部协议时，先输出设计再编码。
5. 完成代码、迁移、测试和文档同步；只在验收证据完整时更新本文件中的阶段状态。

### 1.1 永久产品边界

- 产品名称：**Smart Converge X（SCX）**；中文可使用“瑶知智汇广告平台”。
- 产品定位：单企业运营的广告投放、归因、交易和结算平台；首版**不是对外售卖的多租户 SaaS**。
- 一期重点：效果广告闭环，即“配置投放 → 事件接入 → 归因回传 → 报表对账”。
- 完整 RTB 是后续阶段，不能为了“广告交易平台”名称而跳过基础投放、账务、归因和数据质量。
- 外部凭据、手机号、设备标识、订单号和回调内容均按敏感数据处理；不得写入源码、测试固件、普通日志或文档示例。

### 1.2 不可违背的工程规则

| 领域 | 规则 |
| --- | --- |
| 金额 | 仅使用整数最小货币单位；任何余额变化都写不可变账务流水；禁止直接更新余额。 |
| 事件 | 原始事件不可变；每条事件有来源、接收时间、幂等键、校验结果和处理状态。 |
| 归因 | 归因结果必须包含规则/模型版本、命中触点、窗口和失败原因。 |
| 配置 | 投放、风控、计费和媒体配置均版本化、可审核、可回滚。 |
| 高并发 | 决策和事件入口不得同步依赖慢 SQL 或不受控外部调用。 |
| 幂等 | 所有外部写接口、事件消费者、回传任务和资金操作都必须可幂等重试。 |
| 权限 | 所有读写 API 默认拒绝，按角色授予；资源必须校验所属广告主或媒体。 |
| 变更 | 数据库只能追加迁移，不可修改已执行迁移；破坏性变更须具备兼容期和回滚方案。 |

## 3. 逐阶段实施清单与验收门

### M0：研发基线

**目标：** 建立长期可迭代的工程底座，而不是先堆业务页面。

- 明确单仓库或多仓库边界、分支策略、代码规范、提交规范和 ADR 目录。
- 提供本地一键启动：主数据库、Redis、消息队列、对象存储模拟、邮件/回调 Mock。
- 建立环境配置分层；密钥使用环境变量或密钥服务，提交前扫描泄露。
- 接入 CI：静态检查、单测、迁移验证、镜像构建和依赖漏洞扫描。
- 建立日志规范、统一 `request_id/trace_id`、健康检查和基础指标。

**验收门：** 新开发者在 30 分钟内能启动最小环境；每次提交自动运行检查；密钥不落仓库；可从健康检查和日志定位一个模拟请求。

### M1：身份、主体与访问控制

**目标：** 先确定“谁能操作谁的数据”，避免后续投放和资金数据越权。

- 平台用户、广告主主体、媒体主体、代理关系（如需要）及状态管理。
- RBAC：平台管理员、运营、财务、风控、广告主管理员/只读、媒体管理员。
- 登录、会话、密码策略、MFA 预留、API Key 创建/轮换/撤销、IP 白名单。
- 全量审计：登录、权限、密钥、资金、审核、投放状态和导出。

**验收门：** 两个广告主和两个媒体互不可读写对方资源；API Key 可轮换且旧密钥按窗口失效；高风险操作有审计记录。

### M2：资源、投放与审核

**目标：** 运营可完成一次完整投放配置，但尚不接入真实流量。

- 媒体、App/站点、广告位、格式、底价、状态和接入配置。
- 广告主账户、资金账户、活动、计划、广告、创意、落地页。
- 预算、排期、固定出价、定向、频控、黑白名单和状态机。
- 广告主资质、创意、落地页审核与驳回理由；配置版本与发布/回滚。
- 生成投放预览与“为什么不能投”的模拟诊断接口。

**验收门：** 能创建并审核一个 CPA/CPC/CPM 投放；按预算、时段、地域、设备和频控正确过滤；每个过滤结果有可读原因；审核驳回后不能进入可投状态。

### M3：事件、归因与回传

**目标：** 建立真实效果广告的可信数据闭环。

- 标准事件网关，接入请求、展示、点击和转化；验签、限流、原始事件保存。
- 幂等去重、触点建立、点击优先/展示兜底归因、归因窗口和规则版本。
- 广告主 Webhook、媒体回传任务、重试、死信和人工重放。
- 事件数据保留、脱敏、数据质量状态和异常事件隔离。

**验收门：** 相同事件重复 100 次只产生一个有效业务事件；转化可追溯至投放、创意和媒体；错误签名、超窗、无触点和重复转化均有正确结论；回传失败可重放且不会重复回传。

### M4：数据、账务、对账与结算

**目标：** 让平台的“数据正确”和“钱正确”可被独立核验。

- 事件明细、分钟/小时/日报表、实时数据延迟标记和多维查询导出。
- 充值、冻结、扣费、解冻、退款、调整等不可变账务流水。
- 广告主和媒体账单、计费口径版本、日对账、差异单、结算单、冲正单。
- 数据补算/重放在隔离环境执行，经审批后入正式聚合数据。

**验收门：** 任意报表数字能下钻到明细；账单、流水和余额一致；关闭账单不可被覆盖；模拟重复消息、消费者重启、日切和重放后不产生重复扣费。

### M5：运营、风控与生产治理

**目标：** 从“功能可用”进入“可安全运营”。

- 无效流量规则、设备/IP 风险、媒体质量评分、黑白名单、申诉流程。
- 实时告警、投放/回传/数据延迟大盘、异常自动暂停/降权。
- 运营工作台、审核队列、数据修复申请、故障演练和 Runbook。
- 隐私数据导出审批、删除/保留策略、访问审计和密钥轮换演练。

**验收门：** 可检测并处置模拟刷量；关键链路故障可在 Runbook 下恢复；权限、账务、事件和数据延迟都有可观测指标和告警。

### M6：实时竞价与交易

**目标：** 在 M1-M5 已稳定的基础上增加真正 RTB 能力。

- OpenRTB 适配、请求校验、广告位匹配、候选检索、定向/预算/频控过滤。
- eCPM 排序、底价、一价/二价策略、创意响应、竞价超时和降级。
- 预算预占/确认/释放、竞价日志、胜出/失败通知和交易明细。
- 容量压测、限流、隔离、扩缩容和区域容灾。

**验收门：** 在目标峰值流量下 P99 满足媒体 `tmax`；无超预算；竞价日志可复盘；降级不影响事件接入和账务一致性。

### M7：智能优化

**目标：** 通过可控实验提高投放效果，不能牺牲可解释性和资金安全。

- 特征库、训练样本、CTR/CVR 预估、模型版本、在线服务和回滚。
- 目标 CPA/ROI、预算平滑、冷启动、自动规则和策略实验。
- 实验分流、显著性评估、策略审计、护栏指标和人工接管。

**验收门：** 每次策略/模型变更均可解释、可灰度、可回滚；实验结果有指标证据；没有突破预算、合规或风险护栏。

## 4. Agent 任务粒度与执行模板

一个 Agent 任务只完成一个可验收的纵向切片，例如“计划日预算校验”“点击事件幂等接收”“创意审核驳回 API”。禁止将“完成 M2”作为单个任务。

### 4.1 开工模板

```markdown
## 任务
- 里程碑：M?
- 目标：
- 不做：
- 影响模块/表/API：
- 业务规则来源：
- 风险：
- 验证：
```

### 4.2 完工模板

```markdown
## 交付
- 已实现：
- 变更文件：
- 数据库迁移：
- API/事件契约变更：
- 测试与结果：
- 已知限制：
- 回滚方式：
- 需更新的后续任务：
```

### 4.3 必须先停下确认的事项

- 新增或变更计费、账务、结算、归因窗口、数据保留策略。
- 引入 SaaS 多租户、外部支付、真实媒体流量、真实广告主数据或新的 PII。
- 删除/重写历史数据、执行生产数据修复、轮换线上密钥、暂停大规模投放。
- 改变 OpenRTB 或外部回调的公开兼容性。

## 5. 长期演进机制

### 5.1 ADR（架构决策记录）

在 `docs/广告平台设计/adr/` 中新增不可覆盖的 ADR 文件，格式：`NNNN-简短主题.md`。以下变更必须创建 ADR：技术栈替换、服务拆分、事件协议、归因模型、账务模型、数据仓库、权限模型、外部数据合规策略。

ADR 至少含：背景、决策、候选方案、取舍、影响范围、迁移计划、回滚计划和日期。旧决策不可改写，只能创建“替代”ADR。

### 5.2 Backlog 维护

本文件只记录里程碑，细分任务在同目录 `backlog.md` 维护。任务必须包含：编号、里程碑、优先级、依赖、验收条件、状态、负责人/Agent、最后更新时间。任何未验证的想法标记为“探索”，不得混入已承诺需求。

### 5.3 文档同步规则

| 变更类型 | 必须同步文档 |
| --- | --- |
| 新业务能力 | 01、02、backlog。 |
| 新模块或服务 | 03、ADR、05。 |
| 表/消息/API 变更 | 04、迁移说明、契约测试。 |
| 权限、数据和密钥变更 | 05、ADR（如影响全局）。 |
| 里程碑验收 | `status/CURRENT.md`、backlog、需求追踪矩阵、独立交接和测试报告。 |

## 6. 当前状态与交接

本文件只保存稳定治理规则。当前有效状态维护在 `status/CURRENT.md`；每个任务的详细交接写入 `handoffs/YYYY-MM/任务ID.md`，避免多个 Agent 长期追加同一文件产生冲突。

当前文档只完成“结构草案”，尚未通过产品、财务、技术与合规内容评审，不能标记为完整基线已验收。

## 7. 当前启动建议

下一步应启动 **M0**，而不是直接生成业务代码。M0 的首个任务是把以下尚未决策事项写入 ADR：

1. 技术栈和仓库结构。
2. 首批广告格式与媒体协议。
3. 确认 ADR-0001 的一期“配置投放 + OCPX 归因”边界和首批触点协议。
4. 计费/结算主体、金额精度与时区口径。
5. 数据合规地域、敏感字段最小化规则和数据保留期限。
6. 目标日请求量、峰值 QPS、事件量与报表时效。
