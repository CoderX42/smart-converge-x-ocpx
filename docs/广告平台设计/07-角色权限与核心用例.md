# 07 角色权限与核心用例

## 1. 权限模型

平台采用 RBAC + 资源归属校验。RBAC 决定“能做什么”，资源归属决定“能操作谁的数据”。所有 API 默认拒绝，禁止只依赖前端隐藏按钮。

## 3. 核心用例

### UC-001 创建并上线投放

前置：广告主正常、资质通过、余额/授信充足、媒体库存启用。

主流程：创建活动 → 创建计划 → 设置预算/出价/定向 → 创建广告与创意 → 提交审核 → 审核通过 → 到达排期 → 发布配置 → 开始投放。

异常：创意驳回、余额不足、计划冲突、落地页风险、媒体广告位下线。系统必须显示明确阻塞原因。

### UC-002 接入展示和点击

媒体使用已生效密钥提交事件；网关完成验签、限流、格式校验、幂等接收和原文存档；异步生成有效触点并进入报表。重复事件返回成功接收但不得重复计数。

### UC-003 接入转化并归因

广告主提交转化；系统校验 conversion_id、事件时间和签名，查找归因窗口内触点，应用规则版本生成归因结果，随后创建媒体回传任务和计费事实。

### UC-004 日对账与结算

系统按计费口径生成平台事实 → 载入媒体/广告主对账数据 → 计算差异 → 财务确认/申诉 → 关闭账单 → 生成结算单。关闭后所有调整必须生成冲正或补差记录。

### UC-005 异常投放处置

监控或风控发现异常 → 自动/人工暂停相关计划或媒体 → 保存命中证据和规则版本 → 通知负责人 → 调查 → 恢复、继续限制或关闭 → 形成审计记录。

### UC-006 数据重放

有权限人员提交范围、原因和影响评估 → 审批 → 在隔离模式重放 → 对比预期 → 执行幂等正式修复 → 生成修复批次、影响明细和审计记录。

## 4. 权限验收

- 每个资源型 API 至少覆盖拥有者、非拥有者、平台角色和未授权四类测试。
- 导出、密钥、权限、资金、结算和重放必须有审计。
- 广告主和媒体身份不能通过猜测 ID 访问其他主体数据。
- 超级管理员执行资金和历史数据操作仍需二次确认与原因。
