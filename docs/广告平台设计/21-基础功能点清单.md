# 21 基础功能点清单

- 文档状态：Draft
- 适用产品：Smart Converge X（SCX）
- 目的：把产品需求拆成可直接创建 Backlog、接口、页面和测试任务的基础功能点。
- 范围：单企业运营的广告投放、事件归因、回传、报表和财务基础能力；不包含多租户 SaaS。

## 1. 优先级说明

| 优先级 | 定义 |
| --- | --- |
| P0/MVP | 首个可运行闭环必须具备；缺失则不能验证核心业务。 |
| P1 | 核心闭环稳定后增强；会明显提升运营效率或商业可用性。 |
| P2 | 完整平台、规模化或智能化阶段能力。 |
| OUT | 当前明确不开发，防止 Agent 越界实现。 |

## 2. MVP 最小业务闭环

```text
登录/权限
  → 广告主与媒体主体
  → 活动/计划/广告/创意
  → 素材审核与发布
  → 追踪链接/参数
  → 展示/点击/转化接入
  → 去重与归因
  → 媒体回传
  → 基础报表
  → 计费事实与基础流水
```

## 4. MVP 功能验收组合

首版至少完成下列 12 个组合验收：

| 验收编号 | 组合 |
| --- | --- |
| MVP-01 | 用户登录后只能查看授权广告主/媒体。 |
| MVP-02 | 创建广告主、媒体、App 和广告位。 |
| MVP-03 | 创建活动、计划、广告和创意草稿。 |
| MVP-04 | 创意审核驳回后不能发布；通过后可发布。 |
| MVP-05 | 发布生成版本化追踪链接/参数。 |
| MVP-06 | 展示/点击/转化事件验签后返回 202 接收凭证。 |
| MVP-07 | 重复、乱序、超窗和错误签名按规则处理。 |
| MVP-08 | 转化按点击优先/展示兜底归因并能查询原因。 |
| MVP-09 | 归因成功创建回传任务，失败可重试、死信和重放。 |
| MVP-10 | 有效计费事实生成预算消耗和资金流水，重复不扣两次。 |
| MVP-11 | 报表能从聚合下钻到事件、归因和计费事实。 |
| MVP-12 | 管理员可查看告警、审计和任务失败结果。 |

## 5. 每个功能点的开发任务拆分

一个功能点至少拆为以下任务，不允许只生成一个页面任务：

1. 业务规则与验收用例。
2. 数据模型/迁移/索引。
3. API 或消息契约。
4. 应用服务/领域规则。
5. 权限、审计、日志和指标。
6. 前端页面/操作反馈（若适用）。
7. 单测、组件测试、契约测试和 E2E。
8. Runbook、回滚、文档和交接记录。

## 6. 基础功能点的完成定义

功能只有同时满足以下条件才可标记“已验收”：

- 具备唯一功能编号，并关联需求、业务规则、API/消息、数据和测试编号。
- 正常、异常、重复、无权限和并发路径均有明确结果。
- 代码、迁移、契约、页面和后台任务完成，不留假按钮或空接口。
- 测试证据可复现，包含提交、环境、命令、时间和报告位置。
- 具备日志、指标、审计、告警和回滚/补偿方式。
- 高风险功能由指定产品/财务/技术验收人确认；Agent 不能自行宣布通过。
