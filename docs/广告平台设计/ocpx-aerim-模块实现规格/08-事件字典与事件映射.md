# 08 事件字典与事件映射

> 状态：Draft；依赖当前本地在研事件能力先完成评审与收口
> 现场入口：产品新增/编辑、链接编辑、任务新增/编辑中的事件映射；参考侧未见独立事件字典菜单
> SCX 目标：事件定义 → 渠道映射 → Task 绑定 → Route 发布快照

## 2. 目标管理页 `PAGE-EVENT-LIST`

建议路由放 `views/adx/event/index.vue`，而不是在 `views/system` 建业务域页面；菜单可名“事件字典”。布局包括事件定义页签、渠道映射页签和发布引用查询。

### 2.1 事件定义

| 控件/列 | 规则 |
|---|---|
| 筛选 | 事件 code/name/category/status；改变回第 1 页 |
| 列 | code、名称、标准类型、计费资格、状态、映射渠道数、任务数、版本、更新时间 |
| `BTN-EVENT-ADD` | add 权限；打开定义抽屉 |
| `BTN-EVENT-EDIT` | edit 权限；已发布引用时 code 不可改 |
| `BTN-EVENT-STATUS` | 引用检查；停用后禁止新绑定/发布，不改旧快照 |
| `BTN-EVENT-REFERENCES` | 展示 Product/AppLink/Task/Route 引用，只读 |

### 2.2 渠道映射

| 控件/列 | 规则 |
|---|---|
| Channel/方向 | 必选 Channel；方向 `UPSTREAM_CALLBACK/DOWNSTREAM_DELIVERY` |
| 外部事件 code | 必填；同 Channel/方向唯一 |
| 标准事件 | 必选 ACTIVE EventDefinition |
| 参数模板 | 只能选择 Adapter 支持的白名单映射，不存任意脚本 |
| 状态/版本 | 乐观锁；发布引用后变更产生新版本 |

### 2.3 Product/Link/Task 中的嵌入式编辑器

- “增加事件映射”新增一行；事件不可重复。
- Product/AppLink 仅保存默认策略；Task 创建时显式复制或继承，并显示来源。
- 运行优先级锁定为 `TaskBinding > AppLinkDefault > ProductDefault`；发布时展开为完全值，运行时不再动态继承。
- `dailyLimit` 为非负整数或 null；`unitPrice` 使用 DECIMAL/最小货币单位，必须有币种和计费类型。
- 删除已被 Task 覆盖的默认策略不改变该 Task；删除继承中的默认策略会使 Task 校验失败，要求运营确认。

任务编辑器的现场结构如下，脱敏证据见 [SHOT-TASK-03](assets/2026-08-09/SHOT-TASK-03-exposure-event-mapping-sanitized.png) 和 [SHOT-TASK-04](assets/2026-08-09/SHOT-TASK-04-event-status-lower-sanitized.png)：

| 现场列 | 目标字段 | 规则 |
|---|---|---|
| 上游 OCPX 事件 | `upstreamEventDefinitionId` | ACTIVE 标准事件；同 Task 不重复 |
| 媒体/渠道事件 | `channelEventMappingId` | 来源为所选 MediaAccount 对应 Channel/Adapter 的有效映射；切换 MediaAccount 后清空 |
| 渠道/媒体事件回传比例(%) | `callbackRatioBasisPoints` | `0..100%`；按稳定事实键做确定性采样，重放不改变结果 |
| 限量 | `limitValue` | 非负；现场的 `0` 语义未被界面说明证明。SCX 用 `NULL=不限量`、`0=不允许`，禁止歧义哨兵值 |
| 超量回传 | `overLimitDelivery` | 超量是否仍投递媒体；无论开关如何都保留原始事件和限额决策事实 |
| 垃圾桶 | 删除草稿绑定 | 只影响草稿；已发布 RouteEventSnapshot 不变 |

现场下拉可见的事件名称只证明候选范围，例如激活、注册、付费、次留、拉活/唤醒/唤起/唤端、首活/首唤、首单/首购和完单；实际 code、方向和 Adapter 支持范围必须来自事件字典，不能用中文展示名作为运行键。

## 3. 弹层

### 3.1 事件定义 `POP-EVENT-FORM`

字段：`code`（创建后不可改）、名称、标准事件类型、类别、是否可计费、设备主体类型、描述、状态。校验 code 为 `[A-Z0-9_]{2,64}`，名称 1–64。关闭/取消有未保存确认；提交中禁用。

### 3.2 渠道映射 `POP-EVENT-MAPPING`

字段：Channel、方向、外部 code、标准事件、Adapter 参数模板、成功码规则、状态。切换 Channel 会重置模板；服务端再次校验 Adapter capability。

### 3.3 引用抽屉 `POP-EVENT-REFERENCES`

按 Product/AppLink/Task/PUBLISHED Route 分组；可跳转有权限对象。禁止直接从引用抽屉级联删除；停用前显示活动发布版本数量。

## 4. API

优先复用/稳定当前在研命名：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/adx/events` | 事件分页/幂等创建 |
| GET/PUT | `/adx/events/{id}` | 详情/版本更新 |
| POST | `/adx/events/{id}/status` | 启停用与引用检查 |
| GET | `/adx/events/{id}/references` | 引用摘要 |
| GET/POST | `/adx/event-mappings` | 渠道映射分页/创建 |
| PUT | `/adx/event-mappings/{id}` | 版本更新 |
| GET | `/adx/channels/{id}/event-options` | Adapter 支持事件选项 |
| GET/PUT | `/adx/tasks/{id}/event-bindings` | Task 绑定，随 Task version 更新 |

映射/绑定更新用 `version`；同 Channel/方向/externalCode 冲突返回 `ADX_EVENT_MAPPING_DUPLICATE`。已停用事件绑定返回 `ADX_EVENT_INACTIVE`。发布校验失败使用 `ADX_EVENT_SNAPSHOT_INVALID` 并逐项列明。

## 5. 数据模型

当前本地在研表名可作为评审起点：

| 表 | 所有权/关键约束 |
|---|---|
| `scx_adx_event_definition` | 标准事件；`code` 全局唯一；状态/版本 |
| `scx_adx_channel_event_mapping` | `(channel_id, direction, external_code)` 唯一；引用 definition |
| `scx_adx_monitor_event_binding` | 现有 Monitor 绑定；目标增加 Task 绑定来源/策略版本 |
| `scx_adx_route_event_snapshot` | 与 route version 一一/一对多；发布后不可变 |

目标可新增 `scx_adx_task_event_binding(task_id, event_definition_id, channel_event_mapping_id, source_type, source_id, source_version, unit_price, currency, daily_limit, callback_ratio_basis_points, limit_value, over_limit_delivery, status, version)`；唯一 `(task_id, event_definition_id)`。若最终继续以 Monitor binding 为唯一管理对象，则 Task 保存聚合边界并由服务层维护，不能让两个表同时成为真相。

## 6. 发布与运行链路

1. Task 保存只更新绑定草稿/默认继承来源。
2. 发布服务解析渠道外部 code ↔ 标准事件 ↔ 下游 code，并校验 Adapter、方向、计费资格、限额。
3. 写入 RouteEventSnapshot，包含 externalCode、standardCode、deliveryCode、unitPrice、dailyLimit、callbackRatio、limitValue、overLimitDelivery、规则版本和 schemaVersion。
4. Callback 入口只按 route/version 快照映射；找不到映射进入隔离事实，不猜测事件。
5. 比例采样使用稳定事实键；限额计数用 Redis 短期原子计数，最终采样/限额/超量决策事实写 MySQL；重放不改变采样结果、不重复消耗限额。
6. 扣量生成 adjustment/decision fact，不改写原始 callback。

## 7. 权限、安全与对象范围

权限：`adx:event:view/add/edit/status`、`adx:event-mapping:view/add/edit/status`、`adx:task:event:edit`。EventDefinition 可全局只读；Channel mapping 受 Channel scope；Task binding 取 Task 所有关联范围交集。

事件 payload 可能含设备标识和业务参数：日志只记录 event code、route/version、请求 ID 与字段校验摘要；原 payload 受控存储、限期保留。参数模板不能执行表达式、脚本或任意网络请求。

## 8. 迁移、兼容与观测

- 先冻结标准事件 code 字典和历史 callback 兼容映射，再合并本地在研迁移。
- RouteSnapshot schema N/N-1 兼容；未带事件快照的旧路由按明确 legacy adapter 处理，不能默认映射到任意事件。
- 指标：未映射事件、重复 callback、限额拒绝、扣量决策、快照版本分布、停用事件仍被发布的拒绝数。

## 9. 验收用例

| 层级 | 必测 |
|---|---|
| UI | 动态行重复、上游/渠道事件级联、比例/限量边界、超量开关、继承来源、停用事件提示、引用抽屉和未保存退出 |
| API | code/映射唯一、版本冲突、停用引用、Adapter capability 校验 |
| DB | 四层对象无孤儿；snapshot 不可变；Task/Monitor 真相唯一 |
| 权限 | Channel mapping 与 Task binding 分别按 scope；范围外引用不泄露 |
| 集成 | callback→标准事件→确定性比例→限额/超量→扣量→下游；重复事件不重复采样、计数或计费 |
| 异常 | 未知 code、Adapter 版本变化、Redis 计数故障、旧快照、隔离后重放 |
| 状态门禁 | 本地在研迁移/契约/测试未合并前，文档和实现状态保持 Draft |
