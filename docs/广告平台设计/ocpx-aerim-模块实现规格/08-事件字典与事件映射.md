# 08 事件字典与事件映射

> 状态：S6 模型与 S7 快照发布合同已在源码/隔离本地收口（2026-08-10）；目标环境、第三方 UAT、生产均未验收
> 现场入口：产品新增/编辑、链接编辑、任务新增/编辑中的事件映射；参考侧未见独立事件字典菜单
> SCX 目标：事件定义 → 渠道映射 → Task 绑定 → Route 发布快照

## 1. 证据与现状边界

| 标签 | 事实 |
|---|---|
| `现场实测` | Product 抽屉有“增加事件映射”、事件选择和限量；Link 编辑有事件、考核单价、每日限量；Task 有上游 OCPX 事件、媒体/渠道事件、回传比例、限量、超量回传和删除控制 |
| `界面文案推断` | 产品/链接可提供默认事件策略，但运行时最终采用哪层优先级未由页面证明 |
| `SCX当前工作树-未提交` | V87 已将既有定义/映射演进为 canonical + legacy 双读边界，并新增 Task binding、不可变 RouteEventSnapshot 契约、正式 API/DTO/service 与 Element Plus 页面 |
| `SCX目标设计` | 不另起一套模型；S6 只保存/校验草稿与构建纯配置快照，正式发布、Outbox、实例分发和真实 Callback 闭环仍属于 S7 |

以上能力仍位于未提交工作树。它们已通过本地源码、数据库与构建门禁，但不是目标环境、第三方或生产事实。

## 2. 目标管理页 `PAGE-EVENT-LIST`

建议路由放 `views/ocpx/event/index.vue`，而不是在 `views/system` 建业务域页面；菜单可名“事件字典”。布局包括事件定义页签、渠道映射页签和发布引用查询。

### 2.1 事件定义

| 控件/列 | 规则 |
|---|---|
| 筛选 | 事件 code/name/category/status；改变回第 1 页 |
| 列 | code、名称、标准类型、计费资格、状态、映射渠道数、任务数、版本、更新时间 |
| `BTN-EVENT-ADD` | add 权限；打开定义抽屉 |
| `BTN-EVENT-EDIT` | edit 权限；已发布引用时 code 不可改 |
| `BTN-EVENT-STATUS` | 引用检查；停用后禁止新绑定/发布，不改旧快照 |
| `BTN-EVENT-REFERENCES` | 展示 Product/AppLink/Task/Route 引用，只读 |

### 2.2 渠道映射

| 控件/列 | 规则 |
|---|---|
| Channel/方向 | 必选 Channel；方向 `UPSTREAM_CALLBACK/DOWNSTREAM_DELIVERY` |
| 外部事件 code | 必填；同 Channel/方向唯一 |
| 标准事件 | 必选 ACTIVE EventDefinition |
| 参数模板 | 只能选择 Adapter 支持的白名单映射，不存任意脚本 |
| 状态/版本 | 乐观锁；发布引用后变更产生新版本 |

### 2.3 Product/Link/Task 中的嵌入式编辑器

- “增加事件映射”新增一行；事件不可重复。
- Product/AppLink 仅保存默认策略；Task 创建时显式复制或继承，并显示来源。
- 运行优先级锁定为 `TaskBinding > AppLinkDefault > ProductDefault`；发布时展开为完全值，运行时不再动态继承。
- `dailyLimit` 为非负整数或 null；`unitPrice` 使用 DECIMAL/最小货币单位，必须有币种和计费类型。
- 删除已被 Task 覆盖的默认策略不改变该 Task；删除继承中的默认策略会使 Task 校验失败，要求运营确认。

任务编辑器的现场结构如下，脱敏证据见 [SHOT-TASK-03](assets/2026-08-09/SHOT-TASK-03-exposure-event-mapping-sanitized.png) 和 [SHOT-TASK-04](assets/2026-08-09/SHOT-TASK-04-event-status-lower-sanitized.png)：

| 现场列 | 目标字段 | 规则 |
|---|---|---|
| 上游 OCPX 事件 | `upstreamEventDefinitionId` | ACTIVE 标准事件；同 Task 不重复 |
| 媒体/渠道事件 | `channelEventMappingId` | 来源为所选 MediaAccount 对应 Channel/Adapter 的有效映射；切换 MediaAccount 后清空 |
| 渠道/媒体事件回传比例(%) | `callbackRatioBasisPoints` | `0..100%`；按稳定事实键做确定性采样，重放不改变结果 |
| 限量 | `limitValue` | 非负；现场的 `0` 语义未被界面说明证明。SCX 用 `NULL=不限量`、`0=不允许`，禁止歧义哨兵值 |
| 超量回传 | `overLimitDelivery` | 超量是否仍投递媒体；无论开关如何都保留原始事件和限额决策事实 |
| 垃圾桶 | 删除草稿绑定 | 只影响草稿；已发布 RouteEventSnapshot 不变 |

现场下拉可见的事件名称只证明候选范围，例如激活、注册、付费、次留、拉活/唤醒/唤起/唤端、首活/首唤、首单/首购和完单；实际 code、方向和 Adapter 支持范围必须来自事件字典，不能用中文展示名作为运行键。

## 3. 弹层

### 3.1 事件定义 `POP-EVENT-FORM`

字段：`code`（创建后不可改）、名称、标准事件类型、类别、是否可计费、设备主体类型、描述、状态。校验 code 为 `[A-Z0-9_]{2,64}`，名称 1–64。关闭/取消有未保存确认；提交中禁用。

### 3.2 渠道映射 `POP-EVENT-MAPPING`

字段：Channel、方向、外部 code、标准事件、Adapter 参数模板、成功码规则、状态。切换 Channel 会重置模板；服务端再次校验 Adapter capability。

### 3.3 引用抽屉 `POP-EVENT-REFERENCES`

按 Product/AppLink/Task/PUBLISHED Route 分组；可跳转有权限对象。禁止直接从引用抽屉级联删除；停用前显示活动发布版本数量。

## 4. API

优先复用/稳定当前在研命名：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET/POST | `/ocpx/events` | 事件分页/幂等创建 |
| GET/PUT | `/ocpx/events/{id}` | 详情/版本更新 |
| POST | `/ocpx/events/{id}/status` | 启停用与引用检查 |
| GET | `/ocpx/events/{id}/references` | 引用摘要 |
| GET/POST | `/ocpx/event-mappings` | 渠道映射分页/创建 |
| PUT | `/ocpx/event-mappings/{id}` | 版本更新 |
| GET | `/ocpx/channels/{id}/event-options` | Adapter 支持事件选项 |
| GET/PUT | `/ocpx/tasks/{id}/event-bindings` | Task 绑定，随 Task version 更新 |

映射/绑定更新用 `version`；同 Channel/方向/externalCode 冲突返回 `OCPX_EVENT_MAPPING_DUPLICATE`。已停用事件绑定返回 `OCPX_EVENT_INACTIVE`。发布校验失败使用 `OCPX_EVENT_SNAPSHOT_INVALID` 并逐项列明。

## 5. 数据模型

S6 收口后的四层表：

| 表 | 所有权/关键约束 |
|---|---|
| `scx_ocpx_event_definition` | canonical 标准事件；`STANDARD + channel_id='' + code` 唯一；方向/标准类型/计费资格/config version；V80 行显式 `LEGACY_UNMAPPED` |
| `scx_ocpx_channel_event_mapping` | canonical `(channel_id, adapter_code, direction, external_code)` 唯一；只允许受控模板；V80 三事件映射保持 `LEGACY_UNMAPPED`，不推断 canonical 外部 code |
| `scx_ocpx_task_event_binding` | 唯一 `(task_id, event_definition_id)`；冻结 Channel、mapping、比例、限额、算法和可追踪默认来源 revision |
| `scx_ocpx_route_event_snapshot` | schema 1=`LEGACY_V80`；schema 2=`CANONICAL`；数据库触发器禁止 update/delete，发布后只能新增版本 |

既有 `scx_ocpx_monitor_event_binding` 只保留 V80 兼容读取，不再作为 S6 草稿真相；新写只进入 Task binding。无法确定 Task/Product/MediaAccount 的旧数据保持 legacy/null，禁止按中文名、externalCode 或 URL 回填。

## 6. 发布与运行链路

1. S6 Task 保存只更新绑定草稿/默认继承来源并标记依赖路由待重发；不写 Outbox、不创建承流版本、不改旧快照。
2. S6 快照预览只用当前显式 binding 构建 schema 2 DTO、校验完全值并计算 SHA-256 fingerprint，响应明确 `persisted=false/outboxCreated=false`。
3. S7 发布服务才负责事务写入 RouteVersion、RouteEventSnapshot、发布记录和 Outbox，并将完全配置交给实例。
4. Callback 入口只按 route/version 快照映射；S6 已把 snapshot 0 默认改为隔离，只有显式 `LEGACY_ADAPTER` 才进入旧适配器；未知 code 不猜测。
5. S6 提供 `SHA256_MOD_10000_V1` 纯函数契约与重复事实短路语义；真实 Redis/MySQL 决策事实、计费和下游投递仍由 S7 之后的运行链实现。
6. 原始 Callback/扣量事实不可改写；本轮没有发送真实 Callback、第三方请求或产生计费。

## 7. 权限、安全与对象范围

权限：`ocpx:event:view/add/edit/status`、`ocpx:event-mapping:view/add/edit/status`、`ocpx:task:event:edit`。EventDefinition 可全局只读；Channel mapping 受 Channel scope；Task binding 取 Task 所有关联范围交集。

事件 payload 可能含设备标识和业务参数：日志只记录 event code、route/version、请求 ID 与字段校验摘要；原 payload 受控存储、限期保留。参数模板不能执行表达式、脚本或任意网络请求。

## 8. 迁移、兼容与观测

- 先冻结标准事件 code 字典和历史 callback 兼容映射，再合并本地在研迁移。
- RouteSnapshot schema N/N-1 兼容；未带事件快照的旧路由按明确 legacy adapter 处理，不能默认映射到任意事件。
- 指标：未映射事件、重复 callback、限额拒绝、扣量决策、快照版本分布、停用事件仍被发布的拒绝数。

## 10. S6 实施收口（2026-08-10）

- V87、current schema、required tables 和 verifier 已同步；canonical 必填字段全部显式 `IS NOT NULL`，避免 MySQL `CHECK UNKNOWN` 漏过空值。
- 正式 `/ocpx/events`、`/ocpx/event-mappings`、`/ocpx/tasks/{id}/event-bindings`、options/references/status/snapshot preview 使用专用 DTO；定义写权限、Channel mapping scope 与 Task 的 Advertiser∧Channel∧MediaAccount scope 在服务端重新校验。
- EventDefinition/Mapping 创建幂等、code/外部 code 唯一、乐观锁 409、停用引用预览和已发布 code 保护已落地；审计只记对象、版本和摘要，不记录 payload、Secret 或 URL。
- Task 切换 MediaAccount 时清除不兼容 binding；Product 默认策略仅在创建时作为带 source revision 的模板候选，保存后不动态重读。
- Element Plus 事件字典包含定义、渠道映射、发布引用三页签及 loading、初始空、筛选空、error、403、409、disabled、reference、dirty-close；Task 抽屉已接动态事件行和级联清理，发布按钮仍禁用并标明后续切片。
- 本地 MySQL 8.4 已验证 current schema 空库、pre-V87 升级、V87 重放、legacy 三层不猜测、canonical NULL/比例越界反例及快照不可更新/删除；一次性容器已清理。后端全量测试、契约检查、前端类型/lint/318 单测/生产构建通过。

证据边界：目标数据库未应用 V87，目标服务和浏览器多角色未验收，未执行真实 Callback、外发、计费、重放或第三方 UAT，生产未部署。

### S10 失败补偿的事件快照边界

S10 runtime fact、failure、replay request 和 attempt 只引用接收时冻结的 RouteVersion/EventSnapshot schema version。未知 code、旧版本无快照或映射不完整时保持 `UNMAPPED` 并阻止重放，不按当前 EventDefinition、中文名或 externalCode 补猜。补偿成功只追加新 attempt/result contribution，原失败与原始 Callback 事实保持不变；当前仅有源码、隔离数据库和 fake processor 合同，没有真实 Callback、外发、计费或重放验收。

## 11. S7 快照落地合同（2026-08-10）

- S7 发布事务从 S6 ACTIVE Task binding 构建 schema 2 `CANONICAL` RouteEventSnapshot，逐项冻结 definition/mapping/binding revision、标准/外部 code、受控参数模板、比例、自然日限额、Asia/Shanghai、超量投递和 `SHA256_MOD_10000_V1` fingerprint。
- RouteVersion 额外冻结事件 schema version 和加密 runtime snapshot；运行时只装载 schema 2 且非空的不可变事件快照。旧 schema 0/1 不因 externalCode、中文名或 URL 自动升级，也不进入 S7 ACTIVE 路由缓存。
- binding 变化继续只标 Task/Monitor 待重发；发布新版本不更新或删除旧 RouteEventSnapshot。V87 的 update/delete 触发器及 V88 RouteVersion 不可变触发器共同保护历史。
- 本地只验证快照构建、持久化约束与运行时装载门禁；没有接收或发送真实 Callback，没有采样/限额真实副作用、计费或重放。目标环境与第三方 UAT 仍待验收。
