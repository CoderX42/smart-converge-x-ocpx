## 1. 参考页面规格

`现场实测`：主体上方是五个指标卡，下方为趋势区域。采集时卡片名称为“今日点击、今日激活、昨日次留、今日首活、今日付费”，部分卡片带“较昨日/较前日”对比。实时数值不作为实现常量且未进入截图。

为避免实时指标进入 Git，本页未保存完整仪表盘截图；卡片名称来自本轮现场文本记录，任何数值均不作为实现常量。

| ID | 位置/用途 | 触发与预期 | 状态 |
|---|---|---|---|
| `CARD-DASH-CLICK` | 今日有效点击 | 首次加载并随筛选刷新；展示数值、比较方向、基准说明 | 现场实测 |
| `CARD-DASH-ACTIVATION` | 今日激活 | 口径来自统一事件事实 | 现场实测 |
| `CARD-DASH-RETENTION-D2` | 昨日 cohort 次留 | 分子/分母必须来自昨日 D0 cohort | 现场实测 |
| `CARD-DASH-FIRST-ACTIVE` | 今日首活 | 事件定义不可由页面硬编码 | 现场实测 |
| `CARD-DASH-PAYMENT` | 今日付费 | 只计幂等成功的支付事件 | 现场实测 |

初始加载采用骨架屏；某个卡片失败时显示局部错误与重试，不让整个首页白屏。无数据展示 `--` 和空趋势，不把“无数据”伪装成 0。

## 2. SCX 复用、缺口与目标

| 项目 | 当前 | 目标 |
|---|---|---|
| 摘要接口 | 旧 summary 曾使用独立报表服务 | S9 仅通过 S8 `OcpxUnifiedReportService` 取得卡片、趋势和排行；失活的旧 Dashboard Service/Mapper SQL 已删除，避免双口径回流 |
| 小时事实 | S8 已补冻结维度与 `asOf/finality` | S9 不新增事实表，只补三对象范围查询索引 |
| 页面 | 旧页拼接 summary/account/runtime 多个接口 | S9 改为单一 summary + 同范围 options，并完整表达区块状态 |
| 比较口径 | 页面曾展示未固化同比文案 | S9 由服务端返回上一等长区间、基准值和指标字典计算的变化率 |

Dashboard 是报表投影的快捷视图，不得拥有独立 SQL 口径或页面端计算器。

## 3. 前端组件

```text
dashboard/index.vue
├── DashboardToolbar       时间、数据范围、刷新时间
├── MetricCardGrid
│   └── MetricCard × N     loading/empty/error/ready
├── MetricTrendChart       指标、时间序列、tooltip
└── DashboardFreshness     asOf、聚合延迟、时区
```

- 路由：`/ocpx/dashboard` 或保持现有菜单路径，由服务端菜单下发；组件位于 `views/ocpx/dashboard`。
- 请求采用 `AbortController`/请求序号防止快速切换覆盖新数据。
- 卡片必须显示指标定义入口或 tooltip：数据区间、分子、分母、时区、更新时间。
- 图表 tooltip 不展示无权限维度；颜色不能是唯一的涨跌表达，配合图标和文本。
- 刷新按钮 `BTN-DASH-REFRESH` 只重查，不启动聚合或回补任务。

## 4. API 设计

### 4.1 摘要

`GET /ocpx/dashboard/summary?startDate=2026-08-01&endDate=2026-08-09&advertiserId=...&channelId=...&mediaAccountId=...`

```json
{
  "businessDate": "2026-08-09",
  "startDate": "2026-08-01",
  "endDate": "2026-08-09",
  "timezone": "Asia/Shanghai",
  "asOf": "2026-08-09T10:30:00",
  "freshnessStatus": "PROVISIONAL",
  "metricDefinitionsVersion": "S8_V1",
  "scopeRevision": 12,
  "cacheHit": false,
  "partialFailure": false,
  "cards": { "status": "READY", "data": [] },
  "trend": { "status": "READY", "data": [] },
  "productRanking": { "status": "READY", "data": { "records": [] } },
  "taskRanking": { "status": "READY", "data": { "records": [] } },
  "mediaRanking": { "status": "READY", "data": { "records": [] } }
}
```

`GET /ocpx/dashboard/options` 只返回同一 Advertiser∧Channel∧MediaAccount/Task 范围内的 ACTIVE 候选。两个接口均只要求 `ocpx:dashboard:view`；进入明细报表仍单独要求 `ocpx:report:view`。

### 4.2 趋势

摘要服务内部调用与 `GET /ocpx/reports/hourly` 相同的统一查询服务；趋势固定 `DAY+TIME`，Product/Task/Media 排行由统一服务分页记录按冻结对象汇总后用同一指标字典重算比率，不存在第二套 SQL 或页面公式。

日期闭区间按 `Asia/Shanghai` 转成半开区间，默认 7 日、最大 90 日；事实仍在回补时返回数据并标 `DELAYED/PROVISIONAL`，而不是伪造完整。排行源记录同步扫描上限固定 10,000，超限仅使对应排行区块显式失败，不清零其它区块。

## 5. 数据与缓存

- 不新增 Dashboard 事实表；读取统一小时投影和指标字典。
- S9 使用 45 秒进程内有界缓存；键包含 `userId + scopeHash + scopeRevision + queryHash + metricDefinitionsVersion + factWatermark`。范围 revision 或事实水位变化自然旁路，缓存读写失败回退实时查询，失败区块不入缓存。
- `asOf` 取所有返回指标共同的安全水位，不能用应用服务器当前时间替代。
- 今日数据允许延迟，昨日次留存在 cohort 回填；响应必须暴露 `provisional/final` 状态。

## 6. 权限与安全

| 权限 | 用途 |
|---|---|
| `ocpx:dashboard:view` | 打开首页和读取摘要/趋势 |
| `ocpx:report:view` | 进入明细报表；仅看 Dashboard 不自动获得导出 |

服务端按 `scx_ocpx_user_scope` 过滤所有事实。卡片总数、趋势点、缓存键都必须基于同一范围；不能先查全量再由前端隐藏。

## 7. 失败、灰度与可观测

- 聚合落后：页面显示“数据更新至 …”，指标仍可用但不标最终。
- 部分指标定义缺失：单卡错误 `METRIC_NOT_CONFIGURED`，同时告警，不拖垮其他卡片。
- 时区边界：零点前后以响应 `businessDate` 为准，避免客户端时钟切日。
- 灰度：新维度双读核对，`dashboard_metric_mismatch_total` 超阈值切回旧投影。
- 指标：摘要 P95、缓存命中、聚合延迟、空结果率、权限拒绝数、前端局部错误率。

## 8. 验收用例

| 层级 | 必测 |
|---|---|
| UI | 五卡骨架/空/错误/成功独立；趋势切换不串响应；时区与 asOf 可见 |
| API | Summary 与 Hourly 同指标同范围一致；零分母返回 null；非法时间范围拒绝 |
| 数据 | 小时事实汇总等于摘要；次留按 cohort 而非查询日事件计算 |
| 权限 | 不同对象范围用户看到不同摘要；缓存不跨用户/范围污染 |
| 异常 | 聚合延迟、部分指标缺失、接口超时均有明确降级 |
| 性能 | 常用范围查询 P95、缓存命中率和并发目标由报表 SLO 验收 |

## 9. S9 源码与证据边界（2026-08-10）

- 卡片只展示 `S8_V1` 已锁定的有效点击、激活、激活率、注册、付费；零分母保持 `value=null/status=ZERO_DENOMINATOR`。次留和首活口径尚未进入该指标字典，故不以参考页字段名猜公式或展示伪值。
- 卡片、DAY 趋势和 Product/Task/Media 排行共享一次冻结的对象范围、范围 revision、事实水位、指标版本和最保守 `asOf/freshness`。区块状态独立为 `READY/EMPTY/ERROR/TIMEOUT`，局部失败不会把成功数据清零。
- Element Plus 页面覆盖骨架、初始空、筛选空、全局错误+traceId、403、局部失败、三类 freshness、无敏感权限、小屏和横向滚动；请求序号避免旧响应覆盖新筛选，刷新不清空已成功数据或其它页面状态。
- V90 不新增 Dashboard 事实，只增加 `idx_scx_ocpx_dashboard_scope(advertiser_id,channel_id,media_account_id,time_hour)` 并把旧 `ocpx:dashboard:read` 前向收口为 `ocpx:dashboard:view`。本地合成事实 `EXPLAIN` 证明该索引消除原全表扫描；这不是目标性能结论。
