# 05 链接管理

> 状态：S4 Source + Local Gates Complete / Target Acceptance Pending
> 观察日期：2026-08-09（Asia/Shanghai）
> 参考页面：`/task-link`
> SCX 依赖：Advertiser、接入资料、Product；被 Task、MonitorRoute、事件策略和报表引用
> 证据边界：参考站新增/编辑均只打开到提交前；SCX S4 已完成源码与隔离本地门禁，未部署、未访问真实 URL、未做目标环境或第三方 UAT

本模块把参考页面中的“业务链接配置”映射为 SCX 的 `AppLink` 聚合。必须区分两个不同地址：

- `AppLink.linkUrlTemplate`：运营人员从上游资料粘贴的必填链接模板，可能包含设备宏和查询参数；
- `MonitorRoute.publicUrl`：Task 校验、发布后由 SCX 生成的对外监测入口，属于路由版本，不在 AppLink 表单中生成。

浏览器证据只能证明页面字段与交互意图，不能证明参考系统的后端表、接口、跳转优先级或事件计费实现。

## 1. 现场页面与布局

### 1.1 列表 `PAGE-LINK-LIST`

页面使用全局左侧导航和顶部账号区；内容区依次为面包屑、横向筛选条、数据表和分页。现场筛选顺序为：

1. `名称/描述` 文本框；
2. `选择产品`；
3. `选择上游客户`；

- 链接名称旁有无文字图标，外观类似复制；准确语义必须通过 tooltip 或安全点击补证；

| 状态 | SCX 前端表现 | 服务端/安全约束 |

抽屉从右侧覆盖大部分视口，背景置灰，内部独立纵向滚动。新增标题为 `新增链接`，编辑标题为 `编辑链接`；右上角有 X，底部有 `确定`、`取消`。

截图纠正了两个容易误实现的点：

1. `直达链接` 和 `下载地址` 在重定向关闭时仍然显示，因此联动首先是校验/运行策略变化，不是简单条件显隐；
2. `链接地址` 是必填、可粘贴、编辑态可显示的上游链接模板，不是系统生成且只读的监测路由。

### 3.2 条件与业务规则

| 条件 | 参考界面可确认 | SCX 目标规则 | 待决策/待验证 |
|---|---|---|---|
| Product 变化 | 三个必填选择器同时存在 | 重算 Advertiser，清空不再匹配的 document；服务端校验三者一致 | 参考页是否自动联动未操作 |
| LinkType 变化 | 安卓/IOS/其他单选 | 不立即清空地址；不兼容值需用户确认后清理 | 每类可接受 scheme 和商店域名 |
| Redirect=false | 直达、下载仍可见 | 保存配置但运行链路不执行重定向 | 是否允许两者都空 |
| Redirect=true | 文字说明跳转到下载或直达 | 发布前校验至少一个合法目标；策略写入快照 | deeplink 优先、失败回退等顺序需 RFC/验收 |
| 粘贴链接地址 | 必填；提示自动过滤占位符 | 解析为 `normalizedTemplate + macroSet + validationReport`，原值受控保留 | 参考系统实际过滤清单未知 |
| 新增模式 | 未观察到事件区 | 创建基础 AppLink 后再在编辑态配置事件，或 SCX 评审后统一表单 | 参考系统是否保存后自动进入编辑未知 |
| 编辑模式 | 事件区可见且可为零行 | 事件策略与 AppLink 配置同事务保存；发布后另行冻结 | 单价/限量 tooltip 的精确定义未展开 |

关闭规则：X、取消、Esc 和遮罩点击应走同一个 dirty guard；提交中全部禁用。参考页面只确认 X 与取消存在，Esc、遮罩、未保存确认、成功 Toast、失败定位和列表刷新均未实际执行。

## 4. 领域模型、所有权与状态机

```text
Advertiser 1 ── n Product 1 ── n AppLink
     │                              │
     └── n AccessDocumentVersion ───┘
                                    │
MediaAccount ── Task ───────────────┘
                     │
                     └── MonitorRouteDraft → PublishedRouteVersion
                                                  │
                                                  └── publicUrl + redirect/event snapshot
```

- Product 是 AppLink 的直接所有者；Advertiser 由 Product 唯一确定。
- `documentId/documentVersion` 表示创建该链接时采用的上游接入资料版本，不保存文档永久下载 URL。
- AppLink 是可复用业务目标/上游模板，Task 决定媒体账户、运营人和策略，MonitorRoute 才是可发布执行路由。
- AppLink 事件策略只能作为 Task 绑定的默认模板；运行口径以发布时的 `RouteEventSnapshot` 为准。

状态建议：

```text
ACTIVE ── disable ──> DISABLED
   │                    │
   └──── archive ───────┴──> ARCHIVED
DISABLED ── enable ──> ACTIVE
ARCHIVED ── restore ──> DISABLED
```

恢复后先进入 `DISABLED`，重新检查父 Product、Advertiser、资料、URL 与事件有效性后才可启用。AppLink 更新不直接改写已发布 Route；它只令相关 Task/Route 标记 `CONFIG_OUTDATED`，由明确重发生成新版本。

## 6. REST 接口与并发语义

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| GET | `/adx/app-links` | `adx:app-link:view` | 按关键词、Product、Advertiser、文档、归档和类型分页 |
| POST | `/adx/app-links` | `adx:app-link:add` | 创建 AppLink；`Idempotency-Key` 必填 |
| GET | `/adx/app-links/{id}` | `adx:app-link:view` | 详情、解析报告、事件策略、版本 |
| PUT | `/adx/app-links/{id}` | `adx:app-link:edit` | 携带 `version` 乐观锁更新 |
| POST | `/adx/app-links/{id}/archive` | `adx:app-link:archive` | 引用检查后归档 |
| POST | `/adx/app-links/{id}/restore` | `adx:app-link:archive` | 恢复到 DISABLED |
| POST | `/adx/app-links/{id}/mapping:complete` | `adx:app-link:edit` | 人工补齐存量 Product/资料/URL；完成后仍禁用 |
| POST | `/adx/app-links/{id}/status` | `adx:app-link:status` | 版本检查后启用/禁用；启用重验父对象与 URL 元数据 |
| POST | `/adx/app-links/url:validate` | `adx:app-link:validate` | 只做确定性语法/地址分类/宏预检，固定 `networkCalled=false` |

创建/更新核心请求：

```json
{
  "productId": "<id>",
  "advertiserId": "<由产品校验>",
  "documentId": "<id>",
  "linkType": "IOS",
  "linkName": "<名称>",
  "linkUrlTemplate": "<受控链接模板>",
  "redirectEnabled": false,
  "deeplinkUrl": null,
  "downloadUrl": null,
  "description": null,
  "eventPolicies": [],
  "archived": false,
  "version": 0
}
```

响应只返回 `linkUrlMasked`、`macroSet`、`validationStatus`、`status`、`version` 和可展示关系信息；普通列表不返回完整 query、Secret 或文档永久地址。创建成功是 AppLink 已保存，不等于 Task 已发布，也不生成 `MonitorRoute.publicUrl`。

错误语义：`400 ADX_LINK_TEMPLATE_INVALID`、`403 ADX_LINK_FORBIDDEN`、`409 ADX_LINK_VERSION_CONFLICT`、`409 ADX_LINK_ARCHIVE_BLOCKED`、`422 ADX_LINK_RELATION_MISMATCH`。范围外和不存在统一泛化，避免枚举对象。

## 7. 表结构、索引与删除策略

演进 `scx_adx_app_link`：

| 字段 | 约束/用途 |
|---|---|
| `id` / `biz_code` | 内部主键 / 不可猜测业务编码 |
| `advertiser_id` / `product_id` | 必填；服务端保证 Product 属于 Advertiser |
| `document_id` / `document_version` | 必填；冻结资料版本引用 |
| `normalized_name` / `link_name` | 唯一校验 / 展示原名 |
| `link_type` | `ANDROID/IOS/OTHER` |
| `link_url_template` | 必填；受控存储，禁止普通日志打印 |
| `template_macro_set` | JSON；解析后的宏名集合，不存设备值 |
| `redirect_enabled` | boolean |
| `deeplink_url` / `download_url` | 可空；按协议策略校验 |
| `description` | 可空纯文本 |
| `status` | `ACTIVE/DISABLED/ARCHIVED` |
| `config_version` | 乐观锁；每次语义变更递增 |
| `created_by/updated_by/created_at/updated_at` | 审计字段 |

S4 不新增 AppLink 事件策略表。S2 已确定 Product 事件策略只作为后续 Task binding 默认模板；S5 Task 显式复制后，发布再冻结 RouteEventSnapshot。AppLink 不动态拥有或覆盖事件口径，避免 Product/AppLink/Task 三层默认值互相漂移。

索引建议：唯一 `(product_id, normalized_name, archived_flag)`；普通索引 `(advertiser_id,status)`、`(product_id,status)`、`(document_id,document_version)`。不建立物理外键也必须在服务层和数据库验收脚本验证逻辑关系。禁止物理删除；历史事实和发布快照永远引用当时 ID/版本。

## 8. 跨模块数据联通与运行边界

| 生产者 | 数据/契约 | 消费者 | 方式 | 失败与补偿 |
|---|---|---|---|---|
| Product | `productId + advertiserId + status` | AppLink | 同步校验 | 不一致返回 422；不落半条数据 |
| 接入资料 | `documentId/version/adapterCapability` | AppLink | 同步读取并冻结引用 | 版本不可用则拒绝保存/发布 |
| AppLink | 配置版本、模板解析报告、事件默认策略 | Task/MonitorRoute | 管理面读取；发布时复制快照 | 变更标记关联路由过期，不热改旧快照 |
| Task 发布 | `RouteSnapshot + RouteEventSnapshot` | OCPX 数据面 | MySQL 版本 + Outbox + 配置失效通知 | Outbox 重试；未确认前旧 PUBLISHED 版本继续服务 |
| Feedback | routeId/appLinkId/productId | 去重、跳转、事实 | 数据面同步/异步 | Redis 只做幂等/短期状态，MySQL 保存最终事实 |
| 小时聚合 | appLinkId/productId 等维度 | 链接报表/Dashboard | 统一小时事实 | 迟到数据重算同一分区，不在页面本地计算 |

AppLink 保存事务只写主表、事件策略、审计和配置变更 Outbox；不直接调用第三方。`linkUrlTemplate` 的校验接口禁止实现任意 URL 代理，不访问目标内容。发布事务由 Task/MonitorRoute 模块负责，且只有 `PUBLISHED` 快照可承载流量。

## 9. 权限、对象范围与隐私

权限码：`adx:app-link:view/add/edit/status/archive/validate`，资料查看继续使用文档权限。新建和存量补映射均固定为 `DISABLED`，编辑不接收状态字段，启用/禁用只能通过独立 `status` 权限的版本化端点，不得借 edit 权限绕过。对象范围至少同时满足用户可见 Advertiser、Product 与 Media/Task 关系；前端按钮显隐不是授权边界，服务端必须按对象重验。

| 角色示例 | 查看 | 新增/编辑 | 复制/打开 | 归档 |
|---|---|---|---|---|
| ADX 管理员 | 授权范围全量 | 是 | 独立授权 | 是 |
| 运营 | 分配 Product/Task | 可配置 | 默认仅掩码，按需授权 | 通常否 |
| 报表查看 | 仅汇总/掩码 | 否 | 否 | 否 |
| 审计 | 元数据/审计日志 | 否 | 不取得完整值 | 否 |

URL 可能包含设备宏、渠道参数或签名片段。S4 已做到：列表/详情只返回掩码，完整 URL 仅作为写入值进入服务，实体序列化忽略 URL/请求摘要，变更审计只记 host/指纹/宏名/版本/受影响路由数，Controller 不使用会记录请求体的操作日志。配置预检覆盖 HTTP(S) 协议、userinfo、fragment、host、字面量私网/本地/保留地址、保留后缀、端口、规范化、重复 query key、长度和宏白名单；本阶段明确不解析 DNS、不访问 URL、不跟随重定向。DNS 漂移与每跳目标重验属于真实发布/运行边界，尚未做目标或第三方验收。

## 10. 迁移、灰度、回滚与可观测

前向迁移顺序：新增可空字段与事件表 → 回填 Advertiser/Product/资料/模板 → 双读核对与孤儿清单 → 新 API/UI 灰度 → 关联路由重发 → 完整性通过后收紧非空/唯一约束。无法确认归属或模板的存量链接保持 DISABLED，不自动塞入“默认产品”。

应用回滚只回到兼容旧字段的代码；已经发布的新版本和事实不回滚/覆盖。若新模板造成问题，停用新 Route 版本并重新发布上一份已验证配置，而不是修改不可变快照。

观测指标：保存成功/失败、模板解析拒绝及原因、未知宏、跨广告主拒绝、版本冲突、归档阻塞、过期 Route 数、Outbox 延迟/重试、配置热更新版本差、跳转策略命中/失败（不带完整 URL）。

## 12. 未决策项

1. 重定向启用时，deeplink、Universal Link 和下载地址的选择/回退顺序；
2. Android、iOS、其他三类允许的 scheme、域名和必填组合；

6. 对外复制值采用一次性短链、临时令牌还是受审计的完整模板返回。
