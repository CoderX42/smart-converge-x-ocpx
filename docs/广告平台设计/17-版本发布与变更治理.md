# 17 版本、发布与变更治理

## 1. 版本

应用和公开契约使用语义化版本；数据库迁移、消息 schema 和配置规则有独立不可变版本。构建产物记录提交哈希、构建时间、依赖清单和迁移版本。

## 2. 分支与合并

- 主分支始终可发布；功能使用短分支和小批次合并。
- 每个变更关联 Backlog ID；提交信息说明目的而非仅文件操作。
- 合并前完成代码评审、自动化质量门和文档同步。
- 禁止把实验性破坏变更直接合入生产路径；使用开关或隔离环境。

## 3. 发布流程

需求/风险确认 → 构建与扫描 → 测试环境 → 预生产迁移/回滚演练 → 生成发布清单 → 审批 → 金丝雀/灰度 → 指标与数据校验 → 扩大流量 → 发布完成或回滚。

## 4. 数据库迁移

- 迁移文件只追加不修改；每个环境记录已执行校验和。
- 使用 expand/migrate/contract：先增加兼容结构，再迁移/双写，最后在确认无旧版本后收缩。
- 大表变更评估锁、IO、复制延迟和回滚；必要时在线变更。
- 任何删除字段/表必须经过数据归档、使用扫描和一个发布周期的弃用。

## 5. API与消息变更

兼容变更先扩展生产者/服务端，再升级消费者，最后清理旧字段。破坏性变更需要 RFC/ADR、新版本、双轨期、迁移指南和弃用日期。消息消费者必须在发布前通过兼容性测试。

## 6. 功能开关

开关包含负责人、目的、默认值、作用域、创建/过期时间和回滚方式。资金、归因、风控开关变更必须审计。过期开关应清理，禁止永久堆积。

## 7. 发布校验

- 技术：错误率、延迟、资源、消息积压、数据库/缓存健康。
- 业务：事件量、去重率、归因率、回传率、预算和投放状态。
- 数据：分钟报表水位、关键维度、重复/丢失抽样。
- 财务：计费事实和流水数量、余额勾稽、无异常负余额。

## 8. 回滚

应用、配置和流量路由可快速回滚；数据库采用前向修复或兼容迁移，不依赖破坏性 down 脚本。若已产生事件或资金影响，应用回滚后仍需独立的数据修复/冲正流程。

## 9. 发布记录

每次生产发布使用模板记录版本、范围、迁移、开关、风险、负责人、验证结果、回滚点和后续事项。发布记录不可只存在聊天记录中。
