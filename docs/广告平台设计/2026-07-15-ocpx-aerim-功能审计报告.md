## 阅读结论

本报告的目标是把竞品页面转译为 SCX 的功能输入，而不是证明竞品实现质量或复制其权限模型。当前可识别到 23 个业务路由，覆盖主数据、链接、任务、RTA、数据汇总、转化明细、用户与系统配置。可交互功能分为三类：

1. **已实测**：在测试账号下打开页面并读取可见字段、按钮、分页或校验反馈。
2. **静态确认**：从公开前端路由/菜单代码确认，但没有足够权限或安全理由继续执行交互。
3. **待验证**：需要其他角色账号、真实数据或提交式操作才能确认；不得直接转为 SCX 已接受需求。

## 一、系统定位与角色体系

- 系统类型：面向效果广告/渠道投放运营的后台管理控制台，核心对象是产品、上游客户、客户文档、链接、任务、媒体渠道和转化指标，不是完整 DSP/SSP/RTB 交易台。
- 当前账号可见菜单：工作台（仪表盘）、客户管理、链接管理、任务管理、数据管理 → 任务汇总。
- 角色观察：账号菜单仅有“用户中心”和“退出登录”，没有角色选择、租户切换或“管理员/运营/广告主/媒体方”切换入口。因此本次只能确认当前测试账号权限视图；无法从 UI 证明其他角色菜单差异。
- 权限推测：菜单可见性至少受登录态/RBAC 控制，但本次未调用后端 API 验证服务端资源授权，不能把前端隐藏菜单视为安全边界。
- 产品定位线索：页面字段围绕上游客户、链接、RTA、曝光/点击/激活/留存/支付，偏渠道运营与 OCPX 数据回传管理。

#### 弹窗、抽屉、向导交互路径

1. 列表页 → 新增：点击“新增” → 打开抽屉 → 填写/选择字段 → 点击“确定”触发校验 → 校验通过后才可能保存；本次停在校验层。
2. 列表页 → 编辑：行内点击“编辑” → 打开抽屉 → 读取预填数据；链接编辑额外显示“事件映射”区 → “增加事件映射”新增一行事件/价格/限量控件 → 取消关闭且不保存。
3. 任务页策略展开：打开新增任务 → 开启“后置 RTA”显示 RTA 链接 → 开启“曝光监测”显示曝光上报链接和“大点击”开关 → 取消关闭。
4. 报表导出：打开任务汇总 → 未选日期直接点击“导出数据” → 页面提示“请先选择日期”；未执行带数据导出。

### 关键字段与状态字典（SCX 设计输入）

| 竞品字段/状态 | 业务含义推断 | SCX 设计注意 |
|---|---|---|
| 产品 | 被推广的应用/内容产品 | 独立于广告主主体；需要版本、包体和落地页关系 |
| 上游客户 | 提供转化或接入能力的合作方 | 不直接映射 Advertiser；建议建 Partner/Provider 边界 |
| 客户文档/媒体文档 | 外部接入协议或配置文档引用 | 只保存 OSS 对象元数据或受控外链，不把文档内容当配置事实 |
| 链接类型：安卓/iOS/其他 | 跳转/下载目标的设备类型 | 需要枚举版本和校验规则，避免前端字符串散落 |
| 归档 | 停止日常使用但保留历史数据 | 归档不等于删除；报表需保留历史可见性 |
| 状态：正常/关闭 | 是否继续接收或处理数据 | 应建显式状态机、操作者、原因和生效时间 |
| 曝光、点击、重复点击 | 流量与去重后的基础指标 | 明确去重窗口、时区和延迟，不能直接作为结算事实 |
| 激活/注册/支付/下单 | 转化事件层级 | 事件字典、幂等键、归因窗口和回传状态需版本化 |
| 次留/3留/7留 | 留存衍生指标 | 依赖 cohort 定义和自然日口径，进入 SCX 指标字典 |
| 审减、超量转化 | 规则处理后的转化状态 | 必须保留原始事件与审减原因，支持复核而非覆盖原值 |

### 数据流与状态流转观察

可抽象出以下最小链路：

```text
产品/合作方/文档
        ↓
追踪链接（设备类型、跳转、事件映射）
        ↓
任务（媒体渠道、去重、曝光/RTA开关）
        ↓
点击/曝光 → 激活/注册/支付等事件
        ↓
归因、重复/超量判定、审减、媒体回传
        ↓
按任务/产品/链接/媒体/日期汇总 → 异步导出
```

页面没有展示完整的状态机、审批人、回滚或重放历史；SCX 不能因为存在“禁用/归档/审减”按钮就假定其服务端具备完整审计能力。

### 交互验收清单

- 列表：关键词搜索、级联下拉、日期范围、状态筛选、分页、空态和汇总行。
- 表单：必填校验、条件开关展开、数字最小值、单选枚举、只读回填字段、取消不保存。
- 数据流：导出日期前置校验、事件映射增行、任务策略依赖关系。
- 安全：隐藏路由直达、敏感字段脱敏、主体范围、操作原因、审计记录。
- 异步：导出任务 ID、进度、失败重试、产物过期、死信和人工重放。

## 四、技术观察

- 前端框架/组件库：公开静态资产显示 Vue 3.3、Vite 5、Vue Router 4、Pinia、TanStack Vue Query、OpenTiny Vue 3；页面 DOM 大量使用 `tiny-*` 组件类名。
- 图表库：公开资产同时出现 ECharts 5.x 与兼容版本线索；工作台截图可见趋势折线图。SCX 可复用现有 Vue 3 + ECharts 插件，但指标口径必须独立于图表实现。
- 文件上传/预览：本次可见页面没有素材上传控件；客户文档以关联链接展示，既有站内上传资源路径，也有外部文档链接。SCX 应使用 OSS 对象引用、权限签名和脱敏预览，不直接复制外链。
- 权限控制：前端路由守卫和 Bearer token + `localStorage` 痕迹可由公开 bundle 推测；服务端 RBAC/资源授权未验证。SCX 必须坚持服务端主体归属校验。
- API/部署线索：公开 bundle 出现同源 `/api` 路径和 `Authorization: Bearer` 线索，站点响应头显示 OpenResty；这些是静态资产推测，不等同后端实现证据。
- 安全反面观察：公开构建产物疑似带出构建机环境/秘密类变量。报告不记录具体值；SCX 应限制 Vite 暴露变量为显式公共前缀，并在 CI 做 bundle secret scan。
- 与 SCX 差异：竞品页面聚焦链接/任务/渠道运营，SCX ADR-0001 的一期还要求审核、预算、归因、账务基础闭环；不能因为竞品出现 RTA 字段就提前实现 M7 自动出价。

## 五、SCX 实现建议

### 模块拆分

- `scx-backend`：继续模块化单体；优先落在 `scx-subject`（主体边界）、候选 `scx-delivery`（活动/链接/任务配置）、候选 `scx-tracking`（事件/去重）、候选 `scx-attribution`（归因/回传）、候选 `scx-reporting`（Druid 查询/导出）和既有 `scx-auth`/`scx-system`。
- `scx-fronted/apps/web-ele`：按现有动态菜单与页面白名单增加 `views/delivery`、`views/tracking`、`views/reporting`，复用现有表格、抽屉、权限指令和 ECharts；不新增孤立“竞品复刻”页面。
- 每个长任务都返回任务 ID；导出、批量重试、回传重放不在 HTTP 请求内同步完成。

### 核心难点与应对

1. 外部媒体/客户协议差异：先关闭 Q-001/Q-002，建立适配器与契约样例；不把竞品字段当作标准协议。
2. 事件去重与预算/账务一致性：Redis 只做快速幂等/计数，最终事实落 MySQL/RocketMQ；账务仍以不可变流水为准。
3. 报表口径：明确时区、预估/日结、重复点击、留存率和授信定义；报表不能反向成为账务事实源。
4. 权限：菜单差异只能改善 UX，所有主体 ID、导出范围、回传重放和敏感字段都要在服务端校验并审计。
5. 文件与外链：OSS 保存受控对象，数据库只保存元数据/版本/哈希；外部文档只作为显式集成引用。

### ADR-0002 对齐/冲突

- 对齐：Java 17 + Spring Boot 3.x、Vue 3、MySQL 8、Redis、RocketMQ、Druid、OSS 以及 `scx-backend`/`scx-fronted` 单仓库基线均可承载上述能力。
- 不应照搬：竞品的 OpenTiny/Vite/本地存储 token、公开外链和页面命名不是 SCX 技术决策。
- 阶段边界：链接/任务/事件/报表可作为 M1–M5 候选；RTB/OpenRTB 仍是 M6；自动出价、学习期和实验仍是 M7。
- 决策治理：新增跨领域协议、权限模型、账务模型、归因窗口或服务拆分前先建 ADR；本报告是参考输入，不关闭 Q-001～Q-009。

### 粗略工期（1–2 人）

| 交付 | 估算 | 前提 |
|---|---:|---|
| 主体/合作方边界与链接配置最小切片 | 2–3 周 | Q-001/Q-002 已关闭；只做沙箱数据 |
| 任务、事件映射、去重与回传重试 | 3–5 周 | 契约、RocketMQ、Redis、审计测试齐备 |

| RTB 与自动出价 | 单独 M6/M7 评估 | 不纳入首版排期 |

## 调研限制与后续动作

- 仅以当前测试账号登录视图为准；没有其他角色凭据或角色切换入口，因此不能声称完成管理员/运营/广告主/媒体方的对比矩阵。
- 数据视图存在时间差：首轮取证时任务/任务汇总为空，第二次全路由复扫时 `/summary`、`/task-product` 等页已出现聚合行；报告只记录字段和分页能力，不记录业务行、个人信息或完整指标值。
- 未调用隐藏 API、未下载客户文档、未访问外部文档内容、未提交任何新增/编辑/禁用操作。
- 下一步应由产品/财务/合规基于本报告候选条目关闭对应开放问题，再将接受项拆成正式 `docs/广告平台设计/backlog.md` 条目。
