# 00 愿景、范围与文档治理

## 1. 产品愿景

Smart Converge X 连接广告主预算、媒体流量和转化数据，提供可解释、可核验、可运营的投放与交易闭环。平台优先解决四个问题：流量怎么投、转化归谁、钱如何算、异常如何追溯。

## 2. 成功目标

| 目标 | 衡量方式 |
| --- | --- |
| 投放可控 | 无越权投放、无超预算扣费；所有停止原因可诊断。 |
| 数据可信 | 展示、点击、转化、账单可逐级追溯，重复处理不改变最终结果。 |
| 对接高效 | 新增标准媒体/广告主适配器无需修改核心归因和账务逻辑。 |
| 运营稳定 | 关键链路有 SLO、告警、重放、灰度和灾备。 |
| 长期可演进 | 规则和协议版本化；Agent 任务可独立验收并完整交接。 |

## 3. 产品边界

### 3.1 平台负责

- 广告主、媒体、库存、投放、创意、预算、审核和权限。
- 展示、点击、转化事件的接入、校验、去重、归因和回传。
- CPM/CPC/CPA/OCPX 的计费、账务、对账和结算。
- 运营报表、风控、审计、故障恢复和数据修复。
- 二期以后支持 OpenRTB 竞价和智能优化。

### 3.2 平台暂不负责

- 面向外部客户售卖的软件订阅、套餐、租户域名与租户级计量计费。
- 全能力 CDP/DMP、跨设备身份图谱、用户画像数据交易市场。
- 首版内的程序化保量、复杂 PMP 合同协商及跨国税务。
- 未经专项合规评估的敏感人群定向。

### 3.3 “完整平台”与“首版”的区别

完整平台描述长期目标；首版只交付 M0-M5 中经过确认的纵向闭环。M6 实时竞价和 M7 智能优化不能作为首版上线的前置条件。

## 4. 术语表

| 术语 | 定义 |
| --- | --- |
| Advertiser | 提供预算并购买广告效果的广告主。 |
| Publisher/Media | 提供 App、站点、广告位或流量的媒体。 |
| Campaign | 承载营销目标、总预算和周期的活动。 |
| Ad Group | 承载计费、优化目标、出价和日预算的计划。 |
| Ad | 承载定向、频控、库存范围和落地页的可投对象。 |
| Creative | 实际展示给用户的素材与文案版本。 |
| Impression/Click | 有效展示/点击事件，是否有效由事件校验与风控规则决定。 |
| Conversion | 激活、注册、下单、付费等广告目标事件。 |
| Attribution | 将转化分配给有效展示/点击触点的规则与结果。 |
| OCPX | 以转化目标为优化方向的投放与出价机制统称。 |
| RTB | 在严格时限内完成请求、候选筛选、竞价和响应的实时交易。 |
| Ledger | 只追加、不覆盖的资金流水账。 |
| IVT | 无效流量，包括一般无效和复杂无效流量。 |

## 5. 文档生命周期

每篇规范必须在开头或元数据中明确状态：

| 状态 | 含义 |
| --- | --- |
| Draft | 讨论中，不得据此破坏兼容性或处理真实资金。 |
| Accepted | 已确认，研发和测试必须遵循。 |
| Implemented | 已有实现与测试证据。 |
| Deprecated | 仍兼容但不再新增使用。 |
| Superseded | 已被新的 ADR 或规范替代。 |

变更规则：产品范围、计费、归因、数据保留、权限模型和公开协议的变化必须先创建 RFC/ADR；普通文案、示例和澄清可直接更新，但要维护文档版本记录。
