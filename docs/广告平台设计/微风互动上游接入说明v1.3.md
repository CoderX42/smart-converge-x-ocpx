# 微风互动上游接入说明 v1.3

## 当前交付边界

当前源码新增广告主协议 `WEIFENG`，完成 SCX 媒体 CLICK 到微风互动点击监测接口、微风转化 Callback 到 SCX 事实/扣量/下游回传的双向链路。协议输入来自《API程序化广告对接文档 v1.3》。截至 2026-08-17，生产管理数据与广告主协议映射已登记，“赘婿ios激活”iOS 单任务灰度已具备发布条件；真实微风 Callback 与椰子媒体下游签收尚未完成，因此第三方 UAT 仍未闭环。

文档中的刹车接口和 RTA 不属于本次运行能力：SCX 当前没有可持久化的广告计划启停状态，也没有曝光前 RTA 决策调用点。必须先补领域模型、管理语义、超时降级和独立验收，不能用进程内状态或伪成功接口代替。

## 配置映射

| 微风字段 | SCX 来源 | 说明 |
|---|---|---|
| `aid` | `OcpxPromotionLink.linkUrl` 固定参数 | 直接使用上游开放链接自带值，不从任务 `bizId` 推导 |
| `did` | `OcpxPromotionLink.linkUrl` 固定参数 | 直接使用上游开放链接自带值，不按 SCX 媒体主键映射 |
| 点击地址 | `OcpxPromotionLink.linkUrl` | 保存完整上游模板；路径必须为 `/click`，域名必须命中白名单 |
| Callback | Engine 自动生成 | `GET /ocpx/weifeng/callback`，完整 Feedback 以 AES `ext` 恢复 |

管理端配置：创建或编辑广告主时选择 `WEIFENG`；在广告主页“协议与域名”中维护微风精确域名；推广链接 `linkUrl` 填商务确认的完整点击模板并保留其固定 `aid/did`。监测任务 `bizId` 仅作为通用业务编号，不参与微风 `aid` 生成。协议或允许域名保存后写入 MySQL，并通过刷新标记同步到 Engine，不再修改 yml 或因该配置重新打包。

## 点击字段

Engine 只转发 `CLICK`。请求支持 `caid1/caid2/idfa/oaid/imei/androidid/ip/ipv6/ua/ts/os/osv/model`：

- `ts` 固定发送 13 位毫秒时间戳；输入为 10 位秒时安全换算为毫秒。
- Feedback 入站 `os` 兼容 `0/ANDROID` 与 `1/IOS`；向微风输出固定为 `ANDROID` 或 `IOS`。
- `ua`、`model`、Callback 等宏值严格 URL 编码一次；模板中的固定 `aid/did` 原样保留。
- iOS 至少提供 CAID、IDFA、IP+UA 之一；Android 至少提供 OAID、IMEI、IP+UA 之一。
- `model`、`aid`、`did`、Callback 和有效时间戳缺失时拒绝外发并记录脱敏失败结论。
- 出站 URL 仅允许配置白名单中的公网域名和 `/click` 路径，拒绝内网、回环、用户信息、片段及危险协议。

请求在出站前被拒绝时，流程日志的“说明”列记录不含设备值、完整 URL 或 Callback 密文的稳定原因码，便于媒体按原因调整参数：

| 原因码 | 含义 |
|---|---|
| `WEIFENG_REQUEST_INVALID_OS` | `os` 缺失或不受支持 |
| `WEIFENG_REQUEST_LINK_NOT_FOUND` / `WEIFENG_REQUEST_LINK_URL_MISSING` | 推广链接不存在或未配置完整点击模板 |
| `WEIFENG_REQUEST_MODEL_MISSING` | 下游未传真实机型，或仍传入未替换的 `__MODEL__` |
| `WEIFENG_REQUEST_TIMESTAMP_INVALID` | 时间戳不是 10 位秒或 13 位毫秒 |
| `WEIFENG_REQUEST_CALLBACK_BUILD_FAILED` | Engine 无法生成微风 Callback |
| `WEIFENG_REQUEST_IDENTITY_MISSING` | 缺少当前系统要求的有效归因标识 |
| `WEIFENG_TEMPLATE_*` | 推广链接模板缺少固定参数、必需宏，存在重复参数、未知宏或系统不匹配 |
| `WEIFENG_URL_REJECTED` | 域名、路径、DNS 或其他出站安全校验未通过 |

这些原因码只描述校验结论，不回显原始设备标识、请求 URL、允许域名细节或服务端配置。微风已经响应的 402/500/501 和网络错误继续使用既有结果码记录。

微风 HTTP 状态按 v1.3 记录为：`200` 成功、`402` 暂停投放、`500` 服务错误、`501` 重复点击；网络异常和其他状态均记失败。流程日志不记录完整 URL、设备值或 Callback 密文。

## Callback 事件

自动生成的 Callback 模板包含 `event=__EVENT__&amount=__AMOUNT__&days=__DAYS__`。未被合作方替换的可选宏按空值处理。

| 微风事件 | SCX 动作 | 当前口径 |
|---|---|---|
| `ACTIVATED` | `ACTIVATE` | 激活 |
| `REGISTERED` | `REGISTER` | 注册 |
| `PAID` | `PAYMENT` | 付费，可接收金额 |
| `RETAINED` | `NEXT_STAY` | 留存；`days` 仅校验，当前不单独持久化 |
| `FIRST_DAY_PAID` | `FIRST_ORDER` | 现有首购/首次付费指标，可接收金额 |
| `APP_OPEN` | `EVOKE` | APP 唤起 |

Callback 的首次有效事件进入 MySQL 唯一事实、扣量和报表链路；允许下游回传时继续使用原 Feedback 的通用 `callback_url`。HTTP 200 只表示 SCX 已完成当前处置，不等于下游媒体已确认接收。

## 上线前必需输入

1. SCX 中新建后的广告主主键。
2. 微风确认的正式完整点击模板与域名，模板必须自带固定 `aid/did`。
3. 微风测试环境或可识别的测试计划，以及六类事件中本期需要验收的清单。

完成配置后先在隔离环境用唯一请求 ID 验证点击 200、暂停 402、重复 501、Callback 幂等、金额和最终下游回传。本轮生产主键填充与单任务灰度发布已获授权；不使用伪造 CAID/IDFA 触发生产点击，真实流量验证必须使用媒体替换后的唯一请求 ID，并以微风真实 Callback 和椰子媒体下游确认作为最终验收证据。
