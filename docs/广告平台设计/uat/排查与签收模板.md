# 回执排查与第三方签收模板

## 排查步骤

1. 收集 `event_id`、`monitor_task_id`、媒体请求时间和 HTTP 状态，不收集 Secret 或原始设备号。
2. 在流程日志按事件 ID 查询 Feedback/Callback 的方向、结果、合作方 HTTP 状态和耗时。
3. 核对广告主、推广链接、媒体和监测任务均为 ACTIVE，且链接属于广告主。
4. 核对 Adapter 代码、凭据配置键/版本、上游 URL 和媒体 Callback URL。
5. Feedback 的 202 表示上游已同步成功；502 表示当前调用失败，SCX 不会后台自动重试。
6. Callback 失败同样不会后台重试；双方按事件 ID 对账并决定是否人工再次触发。
